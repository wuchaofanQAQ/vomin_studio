# 资产绑定、依赖解析与 CLI/飞书对接

本 skill 是唯一的视频提示词 skill，既要写出导演级分段文本，也要能走通 `expand → generate → push`。核心约定：**锚点块给 CLI，【资产名】给模型。**

## 1. 双层绑定：锚点块 + 【资产名】

每段提示词最前面放一个**锚点块**（CLI 读它），正文照常用【资产名】（模型读它）。

```
【参考素材锚点】
{角色库：杨广} 图1：【杨广 中年版】，反派，隋炀帝，中年男性，帝王常服
{角色库：姜颜} 图2：【姜颜】，女主角，老者外貌的修行者
{场景库：隋朝皇宫大殿} 图3：【隋朝皇宫大殿】主场景，室内·日，高梁柱、丹陛、垂帘
{剧本分镜表：ep10_p05} 视频1：上一段成片，承接终态姿态

【本段资产锁定】
【杨广 中年版】、【姜颜】、【隋朝皇宫大殿】
...（六块结构照旧，正文只用【】名字，不出现 `{}`）
```

规则：

1. `{}` 只允许出现在【参考素材锚点】块内；锚点块之外出现任何花括号都算错误。CLI 展开时把标记移除、"图N：…"说明保留，素材按图1/图2/视频1 的顺序随 API 传入。
2. 锚点行格式：`{表名：行标识} 图N：【资产名】，身份说明`。行标识必须与库中主键**逐字一致**。身份说明写"是谁/什么场景 + 定位 + 时空"，一行即可，不写长相服装细节（由参考图锚定）。
3. 锚点的【资产名】必须与【本段资产锁定】、正文用的名字一致。库名与范本名不同时（如库里叫"杨广"，提示词里叫"【杨广 中年版】"），在锚点行里写清对应关系，并列入资产映射表。
4. 图片按图1、图2…编号，视频按视频1…编号，顺序连续、不重不漏；同一素材一段内只声明一次。每段独立投喂，所以每段都要重新声明。
5. 需要动作严格衔接上一段时，锚点块加 `{剧本分镜表：上一段ID} 视频1：上一段成片`，并在【本段初始空间】写"起始姿态与视频1结尾一致"。
6. 找不到库中行、素材文件不存在时 CLI 会直接报错，不会静默跳过。所以素材没出图的资产不进锚点块，只进"待补资产"，正文写形制基准。

可引用的表：`角色库`、`场景库`（裸名取主场景；`名·局部·部位` 取局部；存量 `全景基准图（默认）` 行可回退命中；**母版不挂分镜**）、`生图工作台`、`素材库`、`剧本设定`、`剧本分镜表`。`角色档案`、`剧本表` 是文字表，不能引用。

## 2. 段 ID 与分镜表写入口径

一段 = 分镜表一行。

| 分镜表字段 | 一段的写法 |
|---|---|
| 镜头标题 | `第05段 皇宫大殿｜质问杨广` |
| 集号 | 整数 |
| 镜头编号 | 段 ID：`ep{两位集号}_p{两位段序}`，如 `ep10_p05` |
| 台词 | 本段全部对白，每行 `角色：台词`，按时间顺序，逐字取自剧本 |
| 镜头说明 | 一两句话概述本段事件 |
| 视频提示词 | **完整段文本**：锚点块 + 六块结构（CLI 的 `expand` 读这个字段） |
| 人物锁定 | 本段出镜角色名，顿号分隔，库主键 |
| 环境锁定 | 本段场景名，库主键 |
| 时间线 | `00:00–00:20`（本段总时长），镜头级时间码在提示词正文里 |
| 状态 | `待生成` |

注意：CLI 的 `expand` 与 `generate` 读的提示词字段名以 `cli.py` 的 `cmd_expand` 为准（读 `ws.load_storyboard()` 里每个 shot 的 `prompt`）。写入前先 `python cli.py expand $WS --shot <段ID>` 在本地预览，确认字段对得上。

## 3. 依赖解析

写完一集的所有段后，汇总依赖，交 harness 比对资产库：

1. **角色依赖**：逐段清点出镜角色（含有动作的群演）。名称以角色库主键为准；找不到 → `new_characters`，补角色档案和三视图后才能进锚点块。有台词的段注明说话人。检查跨段造型/状态延续（受伤、湿身、换装、版本阶段）。
2. **场景依赖**：逐段标注场景。同地点不同时段/天气视为不同场景（`出租屋（夜）` / `出租屋（日）`，全角括号，不含 `·`）。找不到 → `new_scenes`；需要局部视角的写明 `view`（如 `局部·厨房`），不写则取主场景。空镜也算依赖。
3. **懒加载依据**：先读 `script-to-scene-assets` 产出的场景 `description`（【摄影主轴】P0/P1/M、【画面分层】前景/中景/远景、【空间锚点】），据此设计【本段初始空间】里的站位、机位和纵深，再写镜头。完成本集后，用到的场景全部列入 `scenes`/`new_scenes`，harness 据此只为本集用到的场景出图。
4. **去重**输出：

```json
{
  "scenes": [{"name": "隋朝皇宫大殿"}],
  "characters": ["杨广", "姜颜"],
  "new_scenes": [],
  "new_characters": ["保镖甲"]
}
```

素材就绪前，相关段不得进入生成队列。

## 4. 结构化输出（被 harness 调用时）

在 markdown 输出末尾追加一个 ` ```json:structured-output ` 代码块：

```json
{
  "shots": [
    {
      "shot_id": "ep10_p05",
      "episode": 10,
      "shot_number": "P05",
      "timeline": "00:00-00:20",
      "dialogue": "杨广：人有南北，国有南北吗？",
      "speaker": "杨广",
      "description": "杨广在大殿高位质问姜颜，姜颜答话后被激怒",
      "characters": ["杨广", "姜颜"],
      "scene": "隋朝皇宫大殿",
      "prompt": "【参考素材锚点】\n{角色库：杨广} 图1：…\n…\n【本段资产锁定】…（完整段文本）",
      "status": "待生成"
    }
  ],
  "dependencies": {"scenes": [], "characters": [], "new_scenes": [], "new_characters": []}
}
```

`prompt` 字段是带换行的完整段文本。多段就是 `shots` 数组里多个对象。

## 5. harness 下游步骤

以下步骤**除只读命令外，每一步都要先列清单并得到用户明确确认**（项目铁律：聊天归聊天，写入归写入）：

1. 读 `dependencies`，差分比对场景库：场景/视角缺失 → 调 `script-to-scene-assets` 补出（母版→主场景→局部，派生图须先有母版）；已有 description 但未出图 → 直接出图并过一致性检查。
2. 读 `new_characters` → 调对应 skill 补角色档案和三视图。
3. 素材就绪后，用户确认 → `python cli.py write $WS --table 剧本分镜表 --data '<shots JSON>'`
4. 只读预览：`python cli.py expand $WS --shot ep10_p05`，检查：标记全部解析、锚点说明完整、正文无残留 `{}`、素材清单齐全。
5. 用户确认后 → `python cli.py generate $WS --tts-only` → `python cli.py generate $WS` → `python cli.py push $WS`。

## 6. 成片时长与配音

- **时长**：`generate` 读分镜行 `timeline`（`MM:SS-MM:SS`，如 `00:00-00:20` = 20 秒）作为该段成片秒数，上限 30 秒（Seedance 2.5 单段最长）；解析不出才回退配置 `ark.default_duration`。成本按实际秒数估算。所以 `timeline` 必须写成真实起止，不要留空。
- **配音**：`dialogue` 每行 `角色：台词`（`角色（画外）：台词` 也可），CLI 逐句合成，说话人音色从**角色档案**取（`voice_desc`）；无「角色：」前缀的行归给 `speaker` 字段。对白里的角色名必须与角色档案主键一致，否则用默认音色并警告。
- 多句配音文件以 `;` 分隔写入 `audio_path`，全部作为参考音频传给视频。

## 7. 参考纯净度

- 一个参考图只锁一个对象：角色图锁面容体态，场景图锁地貌建筑材质，不混用。
- 参考图已锁定的长相与服装，正文不重复描写；只写随动作变化的状态（风吹、湿身、迟半拍的衣摆）。
- 参考素材上限：图片最多 30 张、视频最多 10 段（总长 ≤30s）、音频最多 10 段（总长 ≤30s）。主体数量 1~5 个最稳，6~10 个需要抽卡。

## 8. 用户修正

只改被点名的段，以及因终态/初态衔接受影响的后续段；依赖变化时同步更新依赖清单。迭代修复见 `iteration-manual.md`。
