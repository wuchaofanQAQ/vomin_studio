# Director Segment Prompt — 导演级分段视频提示词

## Overview

一段提示词 = 一次生成任务 = 分镜表的一行。把一段戏（6~30 秒）写成固定结构，镜头用精确时间码首尾相接，整段一次提交：

```
【参考素材锚点】   {角色库：…} 图N / {场景库：…} 图N / {剧本分镜表：…} 视频N（给 CLI 展开素材；唯一允许出现 {} 的地方）
【本段资产锁定】   本段用到的全部资产名（与锚点同名）
【本段现场生成】   资产里没有、需要现场补建的东西（空间补全、群演、道具、尺寸）
【本段整体基准】   画风 / 光 / 风 / 声 / 角色状态 / 本段专属物理规则
【本段初始空间】   世界轴、人物站位与朝向、开镜机位、左右轴
【镜头NN｜起止｜标题】  逐镜头句式（对白另起一行）
【本段终态】       最后一帧的人物、位置、姿态、环境状态 = 下一段初态
```

流水线：

```
分集剧本 → ① 意图卡 + 分段 → ② 依赖解析（角色/场景） → ③ 写六块 + 镜头 → ④ 自查 → ⑤ 依赖清单 + 结构化 JSON → harness 写入/展开/生成
```

范本（27 段、278 个镜头）的统计特征，写作时对照：

| 指标 | 范本实测 | 含义 |
|---|---|---|
| 段长 | 6/8/10/15/20/25/30 秒 | 以 15、20、30 秒为主，单镜头段仅用于大场面 |
| 镜头时长 | 中位 1.5 秒；<1 秒占 29%，1~2 秒占 32%，≥5 秒仅 8% | 剪辑节奏快，长镜头只给尺度与情绪 |
| 镜头篇幅 | 约 90 字（<1 秒）到 190 字（5~8 秒），单个超长镜头可到 290+ 字 | 篇幅随时长增长，但不可摊薄动作链 |
| 对白语速 | 中位约 4.5 字/秒，上限约 5.3 字/秒 | 超过 5.3 就必须拆镜或删字 |
| 对白在镜头窗口内的留白 | 起点平均晚约 0.1 秒、终点平均早约 0.14 秒 | 台词几乎铺满镜头窗口 |
| 切镜写法 | 约 73% 的镜头以"切镜头，"开头，首镜头用"开镜，" | 不写转场特效 |

## 核心执行原则（19 条）

> 最高优先级，完整版见 `references/core-principles.md`。与其它文档冲突时以本文件为准。

1. **权威顺序**：最新明确要求 > 最新正式剧本 > 已确认资产映射及逐图证据 > 指定成品结构参考 > 4.1/V5 母版 > 不改剧情的导演推断
2. **新剧本是唯一故事依据**：旧剧本/旧提示词只参考镜头结构，不能恢复新剧本没有的人物、台词、事件、结果、专名
3. **附件与旧指令不自动执行**：默认只是分析材料，除非当前对话明确采用
4. **材料真实完整读取**：剧本读正文/表格/批注/场次/台词/旁白/动作/时长/备注；资产逐页清点、逐张打开，文件名与缩略图不算看过画面
5. **三张台账**：事实台账、资产台账、数值台账；导演推断只补"怎么拍"，不补"发生了什么"
6. **资产名精确锁定**：【精确基础名】，只去最后一个扩展名，版本词与已确认笔误全部保留，不简称、不编号替代、不虚构；**正文所有指称用【资产名】，禁用他/她/自己**；**身体部位也要归属**（`【沈幼怡】的指尖`、`【陈诚】的半张脸`）；锚点 `{表：行标识}` 内不得再套【】，否则解析失败
7. **资产总表不是强制出场表**：只锁真正参与当前画面/对白/声音/事件的资产，排除的必须退出锁定区与正文
8. **无资产元素放入现场生成**：只补可见的外形/材质/尺度/位置/朝向/状态/必要运动，不冒充文件、不补事件
9. **按实际制作场景分段**：地点+时间+连续事件+叙事状态决定，不为凑时长合并、不机械固定秒数
10. **台词时长按自然口语**：4.5~5.2 有效汉字/秒，通常不超 5.5；动作与撞击另预留时间
11. **每段都是独立输入**：时间码从 00:00、镜头从 01 起，资产/空间/人物/道具/天气/光线/声音全部重建，禁止"同上""接上段"
12. **当前可见构图优先**：严格区分可见集/可听集/画外因果集，画外主体不得写进视觉构图，只能用声音、目线、影子、反光、尘雾、光线变化表现
13. **台词逐字且只出现一次**：不润色不删减；画外说话者只作声音身份，不召回画面
14. **真实切镜必须编号**：机位/焦段/可见主体/时间连续性的实质变化都要新镜头，切镜只换观察位置，动作不重开
15. **连续性锁定**：位置/朝向/姿态/重心/支撑/持握/道具/速度/伤势/特效/环境从上一镜结束状态继接
16. **撞击三段**：来势→撞击→主结果；接触先于碎裂、尘浪、震动、声尾；摄影机只在力量传到机位时才反馈
17. **只补导演执行不补剧情**：可补机位/景别/构图/调度/表演/空间/受力/特效动态/光影/声音/切出状态；不可补人物/台词/目的/伤亡/道具功能/留白解释
18. **18 项硬审计全过才写 PASS**
19. **交付真实成品**：不交计划、占位文件、"第一批"或后台处理承诺

## 18 项硬审计（交付闸门）

| # | 审计项 | 判定 |
|---|---|---|
| 1 | 剧情一致 | 无新增/删除人物、事件、结果、专名 |
| 2 | 台词逐字 | 与剧本一致，每句只出现一次 |
| 3 | 资产真实 | 逐张打开核对，非凭文件名 |
| 4 | 标签精确 | 【精确基础名】，版本词/空格/标点保留 |
| 5 | 锁定精简 | 只锁本段实际参与项 |
| 6 | 排除退出 | 不用的资产不在锁定区与正文 |
| 7 | 分段依据 | 地点/时间/事件/状态 |
| 8 | 时间轴 | 0 起、0.5 秒格、镜头 01 起、首尾相接 |
| 9 | 切镜必要 | 实质变化才切，动作不重开 |
| 10 | 可见性分层 | 可见/可听/画外因果分离 |
| 11 | 连续性 | 位置/朝向/姿态/持握/速度/伤势/道具/环境继接 |
| 12 | 撞击因果 | 来势→撞击→主结果 |
| 13 | 数值一致 | 尺度/时长/数量一致且有来源 |
| 14 | 独立输入 | 无"同上/接上段" |
| 15 | 语速合规 | 4.5~5.2 字/秒，动作另计 |
| 16 | 现场生成边界 | 只补可见元素，不补剧情 |
| 17 | 光影声音有源 | 每个光源/声源有物理来源 |
| 18 | 成品完整 | 真实文件、无占位、无"计划/后续" |

全过写 `18 项硬审计：PASS`；任一项不过写 `#n 失败：问题 + 修订动作`，改完重审全表。

## Workflow

### Step 0 — 取料（★ 上下文范围铁律）

设当前要写的集数为 **N**，只读以下内容，缺关键项则要求提供（均为只读命令，无需确认）：

```bash
# 1. 剧本：当前集 + 前 1 集 + 后 1 集（边界集自动缺省；读转化后的 script，默认不含小说原文）
python cli.py read $WS --table 剧本表 --episode N --context 1
# 2. 全局设定（全量）：画风 / 平台调性
python cli.py read $WS --table 剧本设定
# 3. 角色库（形象图状态）+ 角色档案（性格/外貌/音色）
python cli.py read $WS --table 角色库
python cli.py read $WS --table 角色档案
# 4. 场景库（全量，含 description 空间设计，用于依赖比对）
python cli.py read $WS --table 场景库
# 5. 已存在的本集分镜（重写/续写时避免重复）
python cli.py read $WS --table 剧本分镜表 --episode N
```

读取范围铁律：

1. **剧本表只读"当前集 ± 1 集"**，用 `--episode N --context 1`；**严禁不带过滤读全剧，也严禁加 `--with-novel`**——分镜只依据转化后的 `script`，小说原文会让上下文膨胀、注意力稀释，质量明显下降。
2. 前 1 集用来承接结尾钩子、人物进场状态与未完成动作；当前集是拆分对象；后 1 集用来埋钩子、定人物离场状态。只对当前集 N 产出。
3. 第 1 集无前集、最后一集无后集，自动缺省，不补读、不跳集；换集时重新按该集号执行 Step 0。
4. 角色档案体量大时，只读本集及相邻集出场角色的档案。

必须拿到：本集剧本（对白逐字）、可用资产的**确切名称**（角色含版本/阶段，如"杨广 中年版""北极熊，披风版"）、每段目标时长（剧本锁定则照用）。缺资产清单时不要自编名称，缺的列入"待补资产"，在正文里写清外形基准，补图后按同名绑定。

### Step 1 — 导演意图卡与分段

**先做意图卡**（不写进提示词正文，见 `references/cinema-foundation.md`）：这场戏要观众**感到什么**？谁想要什么、谁在阻挡？情绪关键词是什么？再据此选景别、角度、运镜、光，每个选择都要有叙事理由。情绪曲线要起伏：铺垫 → 升温 → 爆发 → 回落。

**再按"一次生成能稳定控制的一场戏"切段**，不是按字数切：

- **同一空间、同一情绪弧、同一批人物**的连续戏放进一段。换场景、换时间、换大状态（飞行 → 落地）才换段。
- 段长取 6 / 8 / 10 / 15 / 20 / 25 / 30 秒。大场面（一击、坠落、尺度奇观）6~15 秒；对白戏与动作戏通常 20~30 秒。
- 一场戏超过 30 秒，在**动作间歇或对白停顿**处断开，前一段终态 = 后一段初态。
- 段内镜头数参考：对白戏 13~20 个，动作戏可到 29 个，大场面 1~7 个。
- **短剧节奏**：开场 1~2 个镜头内进入核心冲突；该有的细节（回忆闪回、标志道具特写、环境氛围）用 0.5~3 秒的短镜头承载，不单独拆段。单集总时长由各段相加决定，不预设固定值。
- **段 ID**：`ep{两位集号}_p{两位段序}`，如 `ep10_p05`。

### Step 2 — 依赖解析（角色 / 场景）

在写正文之前先定资产，规则详见 `references/asset-binding-and-cli.md`：

1. 逐段清点出镜角色，名称以角色库主键为准；找不到 → `new_characters`。
2. 逐段标注场景（场景库按「空间名 + 视角」组织：母版/主场景/局部·部位/闪回/外景），同地点不同时段/天气视为不同场景（名字用全角括号区分，如 `出租屋（夜）`）；找不到 → `new_scenes`。裸名引用默认取该空间的主场景；需要局部时写 `{场景库：出租屋·局部·厨房}`；**母版不挂分镜**。
3. **懒加载依据**：先读场景 `description`（【摄影主轴】P0/P1/M、【画面分层】前景/中景/远景、【空间锚点】），据此设计初始空间的站位、机位、纵深。
4. 引用素材必须已出图；没出图的资产不进锚点块，只进"待补资产"。

### Step 3 — 写六块与镜头

按 `references/segment-template.md` 逐块填写，按 `references/shot-grammar.md` 写镜头。

**写前五块的要点：**

1. **锚点块**：每个出镜角色、每个场景（含空镜）一行，`{表：名} 图N：【资产名】，身份说明`。正文不再出现 `{}`。
2. **资产锁定**只列名字，顿号分隔，不加描述。
3. **现场生成**写"取哪张图的什么 + 补什么"；凡资产里没有的数量、尺寸、道具在此定死。
4. **整体基准**依次写：画风年代 → 光源 → 风向 → 声音 → 角色状态版本 → 本段专属规则（一击只发生一次、量化尺度、连续声桥句）。
5. **初始空间**必须写出：世界轴、每个主体的距离/朝向/相对位置、开镜机位、对话轴与机位侧。

**写镜头的硬规则：**

- 时间码从本段 `0` 起，**最小单位 0.5 秒**（写 `0-0.5s`、`0.5-1.5s`），**首尾相接**，不重叠、不留缝；最后一个镜头终点 = 本段总时长。
- 每个镜头只做**一件看得清的事**；相邻镜头用"承接同一次…"连起动作。
- 句式：`[切镜头，]景别+机位 → 主体【资产】→ 动作链（先后因果）→ 后景 → 运镜与落幅`。
- 写可见的物理状态，不写情绪词；按 `references/seedance-25-rules.md` 五项检查（情绪物理化、全身动力学链、环境动态、光-表面交互、四层画面），长镜头展开，短镜头压缩成一句话。
- 对白按 `references/dialogue-and-audio.md` 另起一行，时间码落在镜头窗口内，语速不超过 5.3 字/秒。
- 动作戏的接触/命中瞬间写 0.2 秒窗口与"短震约画高 X%"；巨物写占画高/画宽百分比并给参照物（`references/physics-and-scale.md`）。
- 每镜运镜尽量不同，动词要狠，物理细节每镜递进不重复。

### Step 4 — 写终态与段间衔接

终态逐项写：主体位置与姿态、手里的物件、环境残留（悬沙、茶气、酒痕）、尚未发生的事。下一段的【本段初始空间】必须与它一致。需要动作严格衔接时，下一段锚点块加 `{剧本分镜表：上一段ID} 视频1`。规则见 `references/continuity-and-anchoring.md`。

### Step 5 — 自查并交付

逐条过 `references/preflight-checklist.md`，再按 `references/core-principles.md` 的 **18 项硬审计**逐项打勾；**再跑机器校验**（硬门槛，任一 ✗ 不许交付）：

```bash
python skills/director-segment-prompt/scripts/check_storyboard.py workspace/{剧名}/drafts/ep01_storyboard.md
```

脚本校验：段头与时长、镜头时间码首尾相接、末镜终点=段时长、对白落在镜头窗口内、语速 ≤5.3 字/秒、情绪禁用词、`{}` 只在锚点块、锚点资产与资产锁定一致、现场生成只用锁定资产、单段 ≤30 秒、无"同上/接上段"省略。

交付时必须写明审计结论：`18 项硬审计：PASS`，或逐条列 `#n 失败：问题 + 修订动作`。**不写 PASS 的稿子不算交付。**

用户要求修改时按 `references/iteration-manual.md` 一次只改 1~2 个变量，改完重过自查与全表审计。

交付物（只读输出，不写入）：

1. 文档头：用法说明、资产绑定说明、**待补资产**、分段索引（`第NN段  标题  X秒`）。
2. 各段提示词正文（含锚点块）。
3. 资产映射表（【资产名】→ 库内行标识/来源/状态）。
4. 依赖清单与结构化 JSON（格式见 `references/asset-binding-and-cli.md`）。
5. 2~4 行说明：段数、总时长、新增场景/角色、引用素材数量。

### Step 6 — 写入与生成（harness 调用时）

按 `references/asset-binding-and-cli.md` 第 5 节：差分比对资产 → 补资产 → 写剧本分镜表 → `expand` 预览 → `generate --tts-only` → `generate` → `push`。

**生产态闸门（调模型前必跑）**：

```bash
python cli.py preflight $WS --episode N
```

只校验不花钱；资产未就绪时输出问题清单并以非 0 退出。`generate` 也内置了同一道闸门，未过会直接拒绝，不会产生模型调用费用。分镜可以先在**预览态**写入评审（审计第 3 项记 `PENDING（预览）`），但**不写 PASS**；只有在生产态、preflight 全过之后才能写 `18 项硬审计：PASS`。

**除只读命令外，每一步先列写入清单、得到用户明确确认再执行**（CLAUDE.md 铁律：聊天归聊天，写入归写入）。注意 `generate` 按各段 `timeline` 真实秒数出片（上限 30 秒），配音按对白逐句从角色库取音色（见 `asset-binding-and-cli.md` 第 6 节）。
