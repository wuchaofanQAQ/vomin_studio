# 分镜依赖解析规则（场景 / 角色）+ 一致性自查

分镜拆完后，必须解析每个镜头依赖的**角色**与**场景**，产出去重依赖清单，并在提示词阶段把依赖转成素材引用（见 `asset-reference.md`）。

## 一、角色依赖解析（Step 3）

1. **逐镜头清点出镜角色**：画面中出现的每个角色都登记角色名（含群演身份，如"保镖甲"）；无人物空镜标"无人物"。
2. **引用必须可解析**：角色名必须能在角色库/角色档案中找到。
   - 找不到 → 标记"需补角色档案"，进依赖清单 `new_characters`。
   - 名称以角色库主键为准（别名/称呼统一映射到正式角色名）。
3. **多人镜头**：列出全部出镜角色（如"张三 + 李四"），不得遗漏背景中正在动作的角色。
4. **跨镜头一致性**：同一角色在不同镜头里的造型、年龄段、标志性特征（伤疤/纹身/道具）必须与角色档案一致；状态变化（受伤/湿身/换装）要在镜头描述中显式延续。
5. **音色归属**：有台词的镜头，台词归属角色 = 该镜头人物锁定中的说话人；TTS 配音按引用顺序的第一个角色匹配音色。

## 二、场景依赖解析（Step 2）

1. **逐镜头标注所在场景**：每个镜头都要有环境锁定（场景名），地点变化必须切新镜头。
2. **引用必须可解析**：场景名必须能在场景库中找到。
   - 找不到 → 标记"需补场景"，进依赖清单 `new_scenes`。
   - 同一场景的不同时段/天气（如"出租屋·夜·雨"）视为独立场景行，不得混用（与 drama-episode-analyzer 的场景抽取规则一致）。
3. **懒加载绑定**：每个场景只有一个**全景基准图**，不再判断多视角。分镜依据 drama-episode-analyzer 产出的场景 `description`（【摄影主轴】P0/P1/M + 【画面分层】前景/中景/远景）来设计本镜头的**站位、人物调度、构图纵深**——先文字设计场景，再据此排镜头。本 skill 在完成本集分镜后，将本集所有用到的场景在场景库更新 `分镜绑定状态: 已绑定`。
4. **跨镜头一致**：同一场景连续镜头的空间结构、光线方向、天气、色调保持一致；按场景 `description` 的画面分层与主轴描述，保证前后镜头在同一空间内的站位/调度自洽。
5. **空镜也算依赖**：无人物的建立镜头同样引用场景素材（全景基准图）。

## 三、依赖清单格式（交 harness 比对资产库）

```json
{
  "scenes": [
    {"name": "出租屋"},
    {"name": "写字楼大堂"}
  ],
  "characters": ["张三", "李四"],
  "new_scenes": [
    {"name": "重生前出租屋"}
  ],
  "new_characters": ["保镖甲"],
  "bind_scenes": ["出租屋", "写字楼大堂"]
}
```

- `scenes` / `characters`：本集全部依赖（去重）。每个场景 = **1 个全景基准图**，不携带 `views`。
- `new_scenes`：现有库中完全不存在的新场景，同样各 = 1 个全景基准图。
- `new_characters`：现有库中不存在、**必须先补资产**才能生成提示词的角色。
- `bind_scenes`：本集分镜实际用到的场景；harness 据此把场景库中这些场景行的 `分镜绑定状态` 更新为「已绑定」。
- harness 比对规则：
  - 场景 → 逐条检查场景行是否存在于场景库、`分镜绑定状态` 是否就绪、全景基准图素材是否已生成；缺失/未绑定的调 `scene-image-prompt` 补出全景基准图
  - 角色 → 走角色档案 + 三视图补生成
  - 素材就绪前，相关镜头的提示词不得进入生成队列

## 四、从依赖到锚定（Step 4）

依赖解析通过后，在每个 CLIP 的**锚定段**（正文之外、STYLE LOCK 之后）逐行声明，每行"引用 + 编号 + 身份说明"：

| 锁定类型 | 锚定段写法 | 锚定素材 |
|---|---|---|
| 人物 | `{角色库：张三} 图1：张三，男主角，28岁外卖员，黑发、左眉伤疤，黑色冲锋衣` | 角色形象图 |
| 环境（全景基准图） | `{场景库：出租屋} 图2：出租屋，张三住处，筒子楼一居室，室内·夜·雨，冷蓝调` | 场景全景基准图 |
| 动作衔接 | `{剧本分镜表：ep01_s01} 视频1：上一镜成片，张三门口动作衔接` | 上一镜成片视频 |

**每个场景只有一个全景基准图**，`{场景库：场景名}` 即解析为该场景的全景基准图；场景一致性由该基准图 + 正文按 `description` 的画面分层/主轴描述共同保证。

**正文（逐秒拆解等）中只写"张三""出租屋"等名字，不出现任何 `{}`。**

完整语法规则见 `asset-reference.md`。
