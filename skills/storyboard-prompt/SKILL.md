# Storyboard Prompt — 分镜拆分 + 依赖解析 + 视频提示词一体化

## Overview

把一集文字剧本一次性转成**可直接生成视频的分镜资产**，流水线四步：

```
分集剧本
  → ① 拆分分镜      逐镜头：时间线 / 景别运镜 / 画面描述 / 台词 / 构图光影
  → ② 依赖场景解析  每镜头环境锁定 → 场景清单（去重 + 新增待补）
  → ③ 依赖角色解析  每镜头人物锁定 → 角色清单（去重 + 新增待补）
  → ④ 生成分镜提示词 每镜头一条 V8 格式 CLIP 提示词，用引用语法锚定素材
```

产出三部分：**分镜表（含提示词）**、**依赖清单**、**人类可读分镜说明**。这是整条流水线的出片入口。

## 素材锚定规则（核心机制）

提示词分两层：**锚定段 + 正文**。

1. **锚定段（CLIP 开头）**：用引用标记列出本镜头参考素材，且**每个引用必须写明"是谁/是什么角色/什么场景"**，按顺序编号：

```
## [参考素材锚定]
{角色库：张三} 图1：张三，男主角，28岁外卖员，黑色短发、左眉骨伤疤，黑色冲锋衣
{场景库：出租屋} 图2：出租屋，张三住处，筒子楼一居室，室内·夜·雨，冷蓝调
{剧本分镜表：ep01_s01} 视频1：上一镜成片，张三门口动作衔接
```

2. **正文（STYLE LOCK / 逐秒拆解）不出现任何 `{}`**，直接用角色名、场景名（如"张三扶住门框""出租屋窗外冷蓝光"）；长相服装由参考图锚定，正文不重复描写。

CLI 生成前解析锚定段：标记移除、映射说明保留，图1/图2/视频1 按顺序作为参考图/参考视频随 API 传递。完整规则、可用表清单与铁律见 **`references/asset-reference.md`（必读）**。

## Workflow

### Step 0 — 加载输入（★ 上下文范围铁律）

设当前要拆的集数为 **N**。只读以下内容，缺关键项则要求提供：

```bash
# 1. 剧本上下文：当前集 + 前 1 集 + 后 1 集（共 3 集，边界集自动缺省）
python cli.py read $WS --table 剧集表 --episode N --context 1
# 2. 全局设定（全量，数据量小）
python cli.py read $WS --table 剧本设定         # 画风 / 平台调性 / 单集时长
# 3. 角色档案与角色库（全量，供出场角色身份与外形核对）
python cli.py read $WS --table 角色库           # 角色名 + 形象图素材状态
python cli.py read $WS --table 角色档案         # 性格 / 外貌 / 音色 / 标志性表达
# 4. 场景库（全量，含 description 空间设计，用于依赖场景比对）
python cli.py read $WS --table 场景库
# 5. 已存在的本集分镜（重拆/续写时，避免重复）
python cli.py read $WS --table 剧本分镜表 --episode N
```

**读取范围铁律（禁止违反）**：

1. **剧集表只读"当前集 ± 1 集"共 3 集**，用 `--episode N --context 1` 过滤；**严禁不带过滤直接 `read --table 剧集表`** 读入全剧——全量剧本原文会导致上下文膨胀、注意力稀释，分镜质量明显下降。
2. 读这 3 集的目的：
   - **前 1 集**：承接上集结尾钩子、人物进场状态与情绪起点、未完成的动作/调度
   - **当前集**：拆分对象（逐场逐镜的完整依据）
   - **后 1 集**：本集结尾要埋的钩子、人物离场状态、为下集做的铺垫
   - 据此把握本集角色**心境弧线、场景布局、人物调度**，但分镜只对当前集 N 产出。
3. 第 1 集（无前集）或最后一集（无后集）自动缺省，不补读、不跳集。
4. 角色档案/角色库/场景库/剧本设定数据量小，全量读；若角色档案体量大，可只读本集及相邻集出场角色的档案（名单从 3 集剧本文本中提取）。
5. 拆解其他集时，重新按该集号执行 Step 0，不沿用上一批 3 集之外的剧本内容。

### Step 1 — 拆分分镜

**导演意图 → 视听转译**：每场戏拆镜头前先标注导演意图卡——这场戏要观众**感到什么**？谁想要什么？情绪关键词是什么？再据此选择景别/角度/运镜/构图/光影，每个视听选择都要有叙事理由，杜绝"为美而美"。详见 `references/cinema-foundation.md`。

逐镜头产出以下 8 个字段（词表与完整示例见 `references/shot-template.md`）：

```
镜头编号 | 时间线(秒) | 镜头焦点调度 | 描述 | 构图提示 | 光影/色调提示 | 台词 | 人物锁定(草稿) | 环境锁定(草稿)
```

| 字段 | 含义 |
|---|---|
| **镜头编号** | 集内顺序号，`shot_id` 规则：`ep{两位集号}_s{两位序号}`，如 `ep01_s01` |
| **时间线(秒)** | 起止秒，如 `00:00–00:08`；从 0 连续分配覆盖整集；**单分镜 5~10s（整数），最长 15s** |
| **镜头焦点调度** | 分镜内景别/角度/运镜序列（如"近景固定 → 特写俯视"），词表见 shot-template.md，AI 适用性已标注；多景别写在同一格，CLIP 内逐秒展开 |
| **描述** | 画面内容：人物动作、表情、环境、氛围（不写情绪词，写可见动作） |
| **构图提示** | 三分法 / 框架构图 / 引导线 / 对称 / 留白 / 纵深分层 |
| **光影/色调提示** | 光影方向 + 色调方向，同场景内保持统一 |
| **台词** | 本分镜对白（无台词留空）；注明说话人，供 TTS 匹配音色 |
| **人物锁定** | 出镜角色名（草稿，Step 3 校验） |
| **环境锁定** | 所在场景名（草稿，Step 2 校验） |

短剧铁律（红果短剧节奏版）：
- **一个分镜对应一行，单分镜时长 5~10 秒（整数），最长不超过 15 秒**；严禁按单镜头平铺（否则会 2~5s 一次 API 调用，分镜数量爆炸且无法实际生成）
- **一个分镜内可含多个景别/运镜微段**（如"近景→特写→全景"或"固定→缓移→固定"），通过 CLIP 逐秒拆解描述，不单独立行
- **红果短剧节奏要求**：节奏极快，开场 1~2 个分镜内必须进入核心冲突；分镜内动作连续、台词短促、不拖沓；但该有的细节场景（回忆闪回、标志道具特写、环境氛围）必须保留，用 5~10s 分镜内的微段承载
- **单集总时长不由剧本设定预设**（不固定 2 分钟），由分镜总时长决定；合计时检验与剧本叙事体量匹配即可

### Step 2 — 解析分镜依赖场景 + 绑定场景

逐镜头校验环境锁定，产出**场景依赖清单**。每个场景只有一个**全景基准图**，不再按镜头区分多视角：

1. 场景名必须与场景库主键一致；库中找不到 → 标记"需补场景"，进 `new_scenes`
2. 同时段同地点的镜头合并为同一场景；不同时段/天气（光影不同）视为不同场景行（与 drama-episode-analyzer 的场景抽取规则一致，如 `出租屋·夜` / `出租屋·日`）
3. **懒加载绑定**：分镜依据 drama-episode-analyzer 已产出的场景 `description`（含【摄影主轴】P0/P1/M 与【画面分层】前景/中景/远景）来设计本镜头的**站位、人物调度、构图纵深**——先文字设计好场景，再据此排镜头。本 skill 在完成本集分镜后，将本集所有用到的场景在场景库中更新为 `分镜绑定状态: 已绑定`（此时该场景的 `description` 已就绪、全景基准图待生成）。
4. 去重输出本集全部场景（每个场景 = 1 个全景基准图）；harness 差分比对场景库，**缺失的场景行**（`分镜绑定状态` 未就绪 / 场景不存在）交 `scene-image-prompt` 补出全景基准图
5. **提示词中先写 `{场景库：场景名}` 占位引用**（解析为场景的全景基准图），不要求素材此刻已存在；真正解析到图片文件是 `expand` / `generate` 时才做

规则与自查见 `references/dependency-resolution.md`。

### Step 3 — 解析分镜依赖角色

逐镜头清点出镜人物，产出**角色依赖清单**：

1. 每个出镜角色（含有动作的群演）都登记，名字以角色库主键为准；空镜标"无人物"
2. 库中找不到 → 标记"需补角色档案"，进 `new_characters`，交 harness 补角色档案 + 三视图
3. 有台词镜头注明说话人；多人镜头列全全部角色
4. 检查跨镜头造型/状态连续性（受伤、湿身、换装必须延续）

规则与自查见 `references/dependency-resolution.md`。

### Step 4 — 生成分镜提示词（V8 · Seedance 2.5）

依赖清单解析通过、且引用素材均已就绪后，为每个镜头生成一条完整 **V8 格式 CLIP 提示词**。

**先做导演推理（不进入提示词正文）**：时间铰链、Shot Function、张力机制、演出弧线、站位、质检（详见 `references/video-prompt-template.md`）。

**V8 十二子段（缺一不可，结构见 `references/v8-structure-template.md`）**：
- STYLE LOCK（①-⑧）：风格锁定 → 色调 → 质感 → 电影质感 → 物理照明 → 人物运动物理 → 场景物理 → N 人声明
- CLIP（⑨-⑪）：首帧声明 → 逐秒拆解 → 微动作全程
- NEGATIVE（⑫）：3-8 项场景特定否定限制

**素材锚定写法（两步，铁律）**：
1. 在 STYLE LOCK 之后写「参考素材锚定」段：每个引用独占一行，按顺序编号，并写清身份——
   - 角色：`{角色库：张三} 图1：张三，男主角，28岁外卖员，黑色短发、左眉骨伤疤，黑色冲锋衣`
   - 场景（全景基准图）：`{场景库：出租屋} 图2：出租屋，张三住处，筒子楼一居室，室内·夜·雨，冷蓝调`
   - 动作衔接：`{剧本分镜表：ep01_s01} 视频1：上一镜成片，张三门口动作衔接`
   - **每个场景只有一个全景基准图**，`{场景库：场景名}` 即解析为该场景的全景基准图；场景一致性由该基准图 + 正文按 `description` 的画面分层/主轴描述共同保证，不再有多视角图
2. **正文（STYLE LOCK 其余子段、⑨⑩⑪）中不出现任何 `{}`，直接用角色名/场景名**；长相、服装、瞳色不写文字，由参考图锚定

完整锚定格式见 `references/asset-reference.md`。

**Seedance 2.5 五大升级（必做，见 `references/seedance-25-execution-model.md`）**：
1. 情绪→物理分解（情绪词全部替换为可见肌肉动作）
2. 全身动力学链（主动件/稳定件/补偿件/不自主反应）
3. 环境动态（每 Shot ≥3-4 个环境动态元素）
4. 光照-表面交互（光源→照射部位→色温混合→反射光→阴影→边缘光）
5. 四层画面枚举（前景/中景/背景/空气层）

**三反原则**：反比喻（删"像/如XX"）、反衣物描写（服装由参考图锚定）、反瞳色（只写"视线看向XX"）。

**Preflight 检查（不可跳过，清单见 `references/video-continuity.md`）**：
- 12 子段完整；三反原则遵守；情绪词已物理化
- 全身动力学链、环境动态、光照交互、四层枚举齐备
- 逐秒拆解连续（上一段末状态 = 下一段初状态）；每镜运镜全不同
- 锚定段每个引用都写清"是谁/什么场景"并按图1/图2/视频1 编号；每个出镜角色/每个场景都有可解析、素材已就绪的引用
- **正文无残留 `{}` 标记**，角色与场景一律以名字指代
- NEGATIVE 针对本场景具体问题（3-8 项）；角色演出匹配人设且彼此分化

### Step 5 — 输出与说明

输出三部分：
1. **人类可读分镜表**（8 字段 + 依赖清单 + 必要的导演推理标注）
2. 2-4 行说明：镜头数、总时长、新增场景/角色、引用素材数量
3. **结构化 JSON**（格式见下，供 harness 写入飞书）

用户修正某镜头 → 只改该镜头及其连续性受影响的后续镜头；依赖变化时同步更新依赖清单。迭代修复见 `references/iteration-manual.md`（一次只改 1-2 个变量，改完重过 Preflight）。

## Automated Mode (Harness Integration)

当被 `ai-drama-harness` 调用时，在 markdown 输出末尾追加一个结构化 JSON 代码块（` ```json:structured-output `）。harness 提取后：先比对 `dependencies` 补资产，再把 `shots` 写入剧本分镜表，用户确认后触发 `generate`。

### JSON 输出格式

````
```json:structured-output
{
  "shots": [
    {
      "shot_id": "ep01_s01",
      "episode": 1,
      "shot_number": "S01",
      "timeline": "00:00-00:03",
      "cinematography": "近景·固定·平视",
      "dialogue": "这不可能...",
      "speaker": "张三",
      "description": "张三坐在桌前，视线猛地抬向手机屏幕",
      "composition": "三分法",
      "lighting": "低调，冷暖对比",
      "characters": ["张三"],
      "scene": "出租屋",
      "prompt": "## [参考素材锚定]\n{角色库：张三} 图1：张三，男主角，28岁外卖员，黑色短发、左眉骨伤疤，黑色冲锋衣\n{场景库：出租屋} 图2：出租屋全景基准图，张三住处，筒子楼一居室，室内·夜·雨，冷蓝调\n\n## [STYLE LOCK]\n①Ultra-detailed cinematic film...（完整十二子段，正文直接用张三/出租屋，不再出现{}）",
      "status": "待生成"
    }
  ],
  "dependencies": {
    "scenes": [
      {"name": "出租屋"},
      {"name": "写字楼大堂"}
    ],
    "characters": ["张三", "李四"],
    "new_scenes": [
      {"name": "重生前出租屋"}
    ],
    "new_characters": []
  },
  "bind_scenes": ["出租屋", "写字楼大堂"]
}
```
````

> **懒加载绑定**：`dependencies.scenes` / `dependencies.new_scenes` 中的每个场景 = 1 个全景基准图（不再有 `views` 多视角）。storyboard 依据各场景 `description`（画面分层/主轴）设计镜头后，将本集用到的场景在场景库更新 `分镜绑定状态: 已绑定`（写入清单的 `bind_scenes`）。已绑定的场景再由 `scene-image-prompt` 懒加载生成全景基准图。

harness 动作：
1. 读 `dependencies`，**差分比对场景库**：逐个 `scenes` / `new_scenes` 条目检查场景行是否已存在、`分镜绑定状态` 是否就绪、全景基准图素材是否已生成
   - 场景行缺失 → 调 `scene-image-prompt` 为该场景出全景基准图
   - 已有 description 但未绑定/未出图 → 先更新 `分镜绑定状态` 为「已绑定」，再调 `scene-image-prompt` 出全景基准图
2. 读 `new_characters`，调对应 skill 补角色档案 + 三视图
3. 将本集场景的 `分镜绑定状态` 更新为「已绑定」：
   ```bash
   python cli.py write $WS --table 场景库 --data '[{"name":"出租屋","bind_status":"已绑定"},{"name":"写字楼大堂","bind_status":"已绑定"}]'
   ```
4. 素材就绪后，用户确认 → `python cli.py write $WS --table 剧本分镜表 --data '<shots JSON>'`
5. 预览展开结果：`python cli.py expand $WS --shot ep01_s01`（检查锚定段映射、正文无残留 `{}`、素材清单齐全）
6. 用户确认后 `python cli.py generate $WS --tts-only` → `python cli.py generate $WS` → `python cli.py push $WS`

> 重要：write/generate/push 都必须在用户明确确认后才执行（见 ai-drama-harness 的写入授权铁律）。
