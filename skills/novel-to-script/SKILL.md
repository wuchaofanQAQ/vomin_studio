# Novel to Script — 小说转剧本

## Overview

Phase B 逐集流程的**第一步（B0a）**。输入是用户上传的小说章节，输出是剧本表中该集的完整一行：

```
小说章节（原文）
  → 小说章节 / 小说内容   原文逐字留存，不改
  → 完整剧本              转化后的结构化剧本（下游唯一剧本来源）
  → 集名 / 状态
```

下游衔接：`script-to-scene-assets` 读 `完整剧本` 定场景、并读当前章 `小说内容` 补空间细节；`novel-to-character-assets` 读 `小说内容` 抽角色；`director-segment-prompt` 只读 `完整剧本` 拆分镜。场次清单与出场角色都由下游 skill 从 `完整剧本` 现算，不再单独存字段。

## 核心铁律

1. **严格 1 章 = 1 集**：每章转成一集，不合并、不拆分。章节过长或过短导致节奏不合适时，只在说明里提示，由用户决定，不擅自改切分。
2. **小说是唯一事实来源**：人物、事件、因果、结局以原文为准。可以改变**表现形式**（叙述→动作与对白），不改变**剧情事实**。
3. **原文逐字留存**：`novel_text` 放该章原文全文，不缩写、不润色、不纠错字；`novel_chapter` 放章节号与章名。
4. **不臆造**：原文没有的设定不补；必须补的过渡动作/场景用【补】标注，列入说明。
5. **只产出草案，绝不擅自写飞书**：先在对话中展示，用户明确确认后才由 harness 执行 `write`。用户提意见时只改草案。

## Workflow

### Step 0 — 加载上下文（只读，无需确认）

设当前章为第 N 章（即第 N 集）：

```bash
python cli.py read $WS --table 剧本设定                      # 画风 / 平台调性 / 世界观 / 单集时长
python cli.py read $WS --table 角色库                        # 角色名统一，避免同人异名
python cli.py read $WS --table 剧本表 --episode N --context 1  # 取前 1 集承接（默认不含 novel_text）
```

- 取前一集的 `script` 末尾，用于承接人物进场状态与情绪起点
- **不要带 `--with-novel`**：小说原文很长，承接只需要转化后的剧本
- 第 1 集无前集，直接转化

### Step 1 — 通读本章，建立索引

通读本章全文，标出：时空切换点、出场人物（正名）、关键动作、对白、内心独白、本章核心事件、章末悬念。

### Step 2 — 转化为剧本

按 `references/adaptation-rules.md` 改编，按 `references/script-format.md` 排版。**格式标准以 script-format.md 为准，不凭记忆写**：

- 抬头两行：`剧名：XXX` / `第N集　集名`
- 场头三行：`1．内景　地点　日` / `人物：A、B` / `备注：光线色调`（可选），场与场之间空一行
- 叙述 → 可见动作（动作行一律 `△` 开头，这是中文影视剧本的格式标准）；心理描写 → 表情/动作/潜台词，必要时少量旁白或 OS
- 对白保留原话精神，口语化、短促；`角色：台词` 顶格，全角冒号
- **前 3 秒**：正文开头两行必须是可拍的悬念或冲突画面（谁在做什么、哪里不对劲），禁止用环境铺陈、天气、空镜、门铃这类"起势"开场；`（字幕）时间地点` 只能跟在冲突画面之后出现
- **可拍性**：每一句台词都要有一个可见动作承载（谁递给谁、谁在看、谁在听、谁转过身）；只写台词不写动作，等于把戏交给导演去猜
- **设备归属**：同一场里有两块屏（手机/电视/电脑）时，动作提示必须写明 `谁的设备 + 朝向谁`，例如"把手机转过来，屏幕正对着陈诚的脸"；禁止只写"盯着屏幕"
- **字幕与屏幕文字**：手机短信、微信、打字内容一律按 `references/script-format.md` 的三种字幕写法标注，**字幕行不挂角色名**（只标 `（字幕·{谁}手机）`），不进台词，下游 TTS 不配音
- 集尾固定 `（本集完）`
- **场景命名归一**：同一地点全剧用同一个名字；与已有场景库同名对齐，发现同景异名在说明中列出对照
- 节奏：开场 1~2 个场内进入冲突，结尾落在钩子上；密度指标见 `references/adaptation-rules.md` 十二（单集 1500~2500 字 / 可拆节拍 ≥40 / 台词 8~30），交付前用 `python skills/novel-to-script/scripts/check_script.py <剧本.md>` 跑一遍

### Step 3 — 提取剧本表其余字段

剧本表只保留基础字段，剧情摘要类信息一律不落表（下游从 `script` 现算）：

- `title`：原章名；无章名则起 10 字内标题并标注"拟名"
- `status`：新转化集写 `草稿`

转化过程中的分析结论（本章核心事件、出场角色、承接/结尾钩子、场次清单）只放进给用户看的说明里，用于自检和下游交接，**不进入剧本表、不 JSON 字段化**。

### Step 4 — 自检与输出

自检（逐条过，不过先改草案）：

| 检查项 | 通过标准 |
|---|---|
| 事实一致 | 事件、因果、结局与原章一致，无新增剧情 |
| 原文留存 | `novel_text` 与上传原文逐字一致 |
| **格式合规** | 抬头、四要素场头、人物行、△ 动作行、`角色：台词`、`（本集完）` 全部符合 `script-format.md`；`check_script.py` 的"格式错误"必须为 0 |
| 场景名归一 | 同景同名，且与场景库已有名字对齐 |
| 角色名一致 | 全部角色名与角色库一致，新角色已单独列出 |
| 钩子 | 结尾有钩子；无钩子明确警示，**不擅改剧情** |
| **可拍性** | 每句台词都能指到一个具体动作/画面；不存在"只有台词没有动作"的悬浮对白 |
| **设备归属** | 涉及手机/屏幕的台词，动作行写明是谁的设备、朝向谁 |
| **△ 标记** | 所有动作/画面行以 `△` 开头；对白、OS、字幕、音效行不带 `△` |
| **禁词零残留** | 全文搜不到特写/近景/中景/全景/推拉摇移/鱼眼/俯拍/机位/镜头切换等镜头语言 |
| **节拍密度** | 可拆节拍 ≥40（跑 `scripts/check_script.py` 校验）；不足就加动作与对白，不是加形容词 |
| **单人场** | 单人无对白场 ≤ 1 个/集，且拆成 ≥3 个具体动作节拍，否则并入相邻场 |
| 内容完整 | 无残留"……待补"类占位 |

> **机器校验是硬门槛**：交付前必须跑
> ```bash
> python skills/novel-to-script/scripts/check_script.py workspace/{剧名}/drafts/ep01_script.md
> ```
> 任何一项 ✗ 都不许交付，也不许写飞书。

输出：①剧本全文 ②字段摘要 ③说明（【补】项清单、新角色清单、场景名归一化对照表、无钩子警示、章节体量提示）。

> **交付前的最后一遍**：把自己当成导演，逐行问"这一行我拍什么"。答不出来的行，要么补动作，要么删。

用户提意见 → 只改草案并重新展示，**不写飞书**。

## Automated Mode (Harness Integration)

被 `ai-drama-harness` 调用时，在末尾输出结构化 JSON。harness **必须在用户确认后**才执行写入。

````
```json:structured-output
{
  "剧本表": [
    {
      "episode": 1,
      "title": "重生第一夜",
      "novel_chapter": "第1章 重生",
      "novel_text": "（该章小说原文，逐字保留）",
      "script": "（转化后的完整剧本，带结构化场头）",
      "status": "草稿"
    }
  ],
  "new_characters": ["保镖甲"],
  "scene_name_map": [{"原文称呼": "张三的家", "归一为": "出租屋"}]
}
```
````

- `剧本表` 的 `episode` 是 match key
- `new_characters` / `scene_name_map` 仅供展示与下游参考，**不写入飞书**

### 确认后的写入（harness 执行，需用户确认）

```bash
python cli.py write $WS --table 剧本表 --data '<剧本表部分>'
```

写入清单须列明：集号、章节、`novel_text` 字数、`script` 字数、状态（`草稿`）。

## 特殊情况

- **用户直接上传已写好的剧本**（不是小说）：不走本技能，由 harness 直接写入 `script`，`novel_chapter` / `novel_text` 留空。
- **存量数据**：经 `migrate-schema` 迁移后，旧数据在 `小说内容` 里、`完整剧本` 为空、状态为 `待转剧本`——这些行就是本技能的待办输入，转化后覆盖 `script` 并把状态改为 `草稿`。
- **章节缺失/乱序**：只按用户给出的章节转化，不补章、不重排，缺失处在说明里提示。
