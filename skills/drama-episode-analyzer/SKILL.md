# Drama Episode Analyzer — 逐集预分析

## Overview

Phase B 逐集流程的**第一步（B0）**。在 storyboard-prompt 拆分镜之前，先通读当前集剧本原文，完成两项预分析：

1. **场景空间设计**：为该集出现的每个场景产出结构化空间设计文档，写入场景库 `description` 字段。方位用北/南/东/西。该文档直接作为下游 scene-image-prompt 的 `<SPACE MAP>`，不再改写方位，也不自行推导空间结构。
2. **新角色识别与档案产出**：扫描剧本中的命名角色，标记角色库中不存在的新角色，为每个新角色产出完整 8 模块角色档案（角色库精简版 + 角色档案完整版），供三视图出图、分镜演出、配音等下游 skill 直接消费。

**幂等规则**：已有 `description` 的场景自动跳过，不重复分析。同一场景只需设计一次，后续集复用。

## 核心纪律

- **设计必须扎根剧本**：角色在剧本中开门、坐沙发、看窗外——这些动作暗示了空间结构。空间设计从剧本原文中发现，不凭空臆造。
- **缺失项标"未指定"**：剧本未描述的空间细节标注"未指定"，不替编剧脑补。
- **画风继承剧本设定**：场景风格/材质从剧本设定的画面风格字段继承，不自行发明。
- **只分析不写入**：产出草案后由 harness 展示确认清单，确认后才 write。

## Workflow

### Step 0 — 加载上下文

读取当前集 N 的上下文（只读，无需确认）：

```bash
python cli.py read $WS --table 剧集表 --episode N --context 1   # N-1/N/N+1 共 3 集
python cli.py read $WS --table 剧本设定                          # 画风/世界观
python cli.py read $WS --table 场景库                             # 检查已有 description
python cli.py read $WS --table 角色库                             # 检查已有角色
```

从剧集表中提取当前集的场景列表（`scenes` 字段），逐个检查场景库：
- 已有非空 `description` → 加入 `skipped_scenes`，不重复分析
- 无 `description` 或场景库中不存在 → 加入待分析清单

### Step 1 — 场景空间设计

对待分析清单中的每个场景，通读剧本原文中该场景的所有段落，分析角色与空间的互动（走进门、坐在沙发上、转身看向窗外、从厨房端出盘子等），产出结构化空间设计文档。

设计文档包含 6 个模块（详见 `references/spatial-design-template.md`）：

1. **场景基础**：类型(室内/室外)、地点、风格(继承设定)、氛围(光线/天气/色调)、材质体系
2. **功能区划分**：A/B/C 区域各是什么功能区、面积比例、空间关系
3. **摄影主轴定义**：P0(站位端锚点) → P1(朝向端锚点)、M(主体锚点)、主轴方向说明
4. **家具/道具清单与位置**：逐一列出每个物件的区域、相对主轴方位、邻近物件关系
5. **门窗朝向清单**：每个门/窗的位置、开向、铰链侧/朝向
6. **光源位置清单（★必填）**：数量、位置、类型、色温、照射方向、光影关系

**摄影主轴选择原则**：
- P0 通常选主入口/门洞（角色最常进出的位置）
- P1 通常选主背景墙/主窗（空间纵深的终点）
- M 选场景中心主体（角色互动最多的物件/区域）
- 如剧本中有明确的"镜头方向"暗示（如"从门口望去"），优先采用

**description 字段格式**（紧凑文本，\n 分隔模块）：

```
【场景基础】室内·现代都市小户型出租屋，当代写实风，夜间·雨天·冷蓝调，水泥墙面+复合木地板+廉价板式家具
【功能区】A区=书桌工作区（西墙，面朝P1时的左手侧墙）B区=床铺休息区（东墙，面朝P1时的右手侧墙）C区=门厅（北墙，P0）
【摄影主轴】P0=入户门（北墙） → P1=窗台（南墙） M=书桌与办公椅。轴线从北指向南。面朝 P1 时，左手侧墙是西墙，右手侧墙是东墙
【物件清单】书桌：A区，西墙，桌面有笔记本电脑和外卖盒；办公椅：书桌东侧，面朝书桌；单人床：B区，东墙，床头朝北；衣柜：东墙，床尾与南墙窗台之间；入户门：北墙正中，门扇朝室内开，铰链在东侧，正视图不入画；窗台：南墙正中，窗户朝南
【门窗】入户门：北墙正中，朝内开，右侧铰链；窗户：南墙正中，朝南，推拉式
【光源】窗外路灯（主光）：南墙窗户外，冷白色光从窗外照入，照亮书桌台面和床脚区域，在衣柜侧面形成长条阴影；书桌台灯：A区书桌左上角，暖黄光，照亮书桌台面和键盘区域，与窗外冷光形成冷暖对比
```

### Step 2 — 新角色识别与档案产出

扫描当前集剧本原文中出现的所有命名角色，与角色库对比：
- 已在角色库 → 跳过
- 不在角色库 → 产出完整角色档案（双表结构）：

**角色库（精简版，供生图/TTS）**：
- `name`：角色名
- `char_type`：核心/配角/路人
- `appearance`：外貌一句话摘要（喂给三视图）
- `voice_desc`：音色描述（喂给 TTS）
- `source`：固定为 "原始采集"

**角色档案（完整 8 模块，供编剧/分镜/战斗）**：按 `references/bible-template.md` 的 A–H 模块逐字段抽取：
- `basic_info`(A)：角色名、定位、出场集数、身份、性别、关系
- `style_desc`(B)：画风基调（继承剧本设定）、主色调、整体气质
- `voice_desc`(C)：音色、语速语气、口音
- `appearance`(D)：脸部细节、身体、服装配饰、标志性特征
- `personality`(E)：性格、动机、弱点、说话风格
- `battle_desc`(F)：战斗风格、招式、阶段状态、特效
- `signature_expr`(G)：经典动作、口头禅、标志性道具
- `notes`(H)：来源集数、缺失项清单、资产状态

**抽取规则**（详见 `references/role-extraction.md`）：
- 缺失项标"未指定"，不臆造
- 标志性特征（伤疤/纹身/道具）是一致性锚点，必须完整保留
- 画风基调从剧本设定继承
- 多集描述冲突时以首现版为准，标注冲突

### Step 3 — 输出

产出人类可读摘要 + 结构化 JSON。摘要包含：
- 本集场景清单：哪些产出了新设计、哪些复用已有设计
- 每个新设计的空间要点摘要（一句话概述 P0→P1 主轴和核心家具）
- 新角色列表（如有）
- 缺失项/不确定项汇总

````
   ```
````

4. 完成后进入 B1: storyboard-prompt
