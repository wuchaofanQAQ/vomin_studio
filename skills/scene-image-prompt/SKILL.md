# Scene Image Prompt

## Overview

把剧本设定 + 分集里的场景描述，转成**可直接投喂豆包 seedream** 的场景**全景基准图**提示词。每个场景默认只出一张全景基准图，纯空镜无角色。

**本 skill 是执行者**：需要出哪些场景由上游决定（storyboard-prompt 定义需求并绑定场景 → harness 差分比对 → 本 skill 执行出图提示词）。

每个场景 = 1 个全景基准图，默认不生成其他视角图（无反打图 / 45°俯视 / 90°垂直俯视）。

## 相机参数标准（全景基准图）

每个场景默认只生成一张全景基准图，机位按以下标准设定：

**室内场景（占 90% 短剧场景：客厅、卧室、书房、病房、办公室）**
- 机位高度：**1.5 米**，成年人平视高度（不仰、不俯；仰俯留给分镜镜头）
- 水平角度：**45° 斜角**，站在房间一个角落外侧，看向对角。例：矩形客厅四角 A/B/C/D，相机放靠近 A 角位置看向对角 C；画面里同时看见【A 相邻的两面墙】，沙发、茶几、门窗这些核心陈设都落在画面内
- 镜头焦距：**35mm**（小广角）

**室外场景（街道、别墅大门、停车场、医院门口）**
- 常规外景：平视，45° 斜侧，35mm，略微拉开距离，拍到主体建筑 + 周边环境。例：别墅大门基准图，斜着拍大门，同时拍到一部分院墙和门前空地，不是正对着大门
- 狭长外景（走廊、地下通道）：可稍微偏 **30°**，不要正对着通道深处（正对通道容易产生隧道视觉，机位很难复用）

**特殊固定机位场景（监控视角、固定窗边机位）**
- 只有这类特殊固定机位场景才单独改相机；其余一律用上面的默认标准。

> 每个场景的【基准图机位】由 drama-episode-analyzer 在 description 中写定（含本场景选用的角落/朝向），本 skill 直接采用，不自行重选。

## Workflow

### Step 0 — 接收场景清单

harness 传入待出图的场景清单，每个场景 = 1 个全景基准图（`分镜绑定状态` 已就绪或待绑定）。例如：

```
待出图场景（全景基准图）：
- 出租屋
- 写字楼大堂
- 停车场
```

如果某场景的全景基准图已存在（场景库中已有 `ref_image` 素材），则跳过该场景。

### Step 1 — 读取空间设计（校验 description）

从场景库读取每个待出图场景的 `description` 字段。该字段由 `drama-episode-analyzer` 产出，已经是北/南/东/西。本 skill 直接复用为 `<SPACE MAP>`，不改写物件位置和属性。

**校验规则**——逐条检查 description 是否包含：
- 【摄影主轴】含 P0、P1、M 三个锚点
- 【物件清单】至少列出 3 个物件及其方位
- 【光源】至少 1 个光源含位置和色温
- 【画面分层】含前景/中景/远景三个层次描述（★ 必须，决定构图纵深）
- 【基准图机位】含本场景选用的机位角落/朝向

**如果 description 为空或校验不通过**：报错并列出缺失项，不继续出图。harness 需先为该场景运行 `drama-episode-analyzer` 补充空间设计。

**如果校验通过**：将 description 加载为当前场景的空间锁定上下文，供 Step 2 组装 `<SPACE MAP>` 段。

### Step 2 — 全景基准图

所有场景都只需此步骤，每个场景只出一张全景基准图，无其他视角。

**画面要求：**
- 纯空镜，16:9 横版，无角色无文字
- 按 description 的【基准图机位】设机位（室内 1.5m 平视、45° 斜角、35mm；室外拉开距离；狭长外景偏 30°）
- 画面要包含**上下左右四面以及背景信息**，有纵深空间感；前景/中景/远景按【画面分层】落位
- 所有物件的空间关系、门/窗朝向、光源位置必须精准锁定

**提示词组装：** 按 `references/prompt-blueprint.md` 写，顺序为 `<HEADER>` → `<STYLE LOCK>` → `<LOCK>` → `<SPACE MAP>` → `<CAMERA>` → `<QUALITY>`。一张图一条提示词。

写完后核对 P0、P1、M、物件、门窗、光源、画面分层与 description 一致。有缺失或和 `<CAMERA>` 矛盾就改完再输出。

输出提示词 + 说明（场景类型、P0→P1 主轴、基准图机位、光源位置、缺失项）+ 校验声明。

## 跨场景一致性（共享材质/物件锚点）

同一部短剧里，多个场景常共享同一套空间与物件——如同一公寓的走廊与室内、跨场景出现的同一扇深色入户防盗门、同一套墙面/地板/家具。这些**跨场景共享部分**的材质与风格必须一致，否则成片会出现"门不对版、装修割裂、材质跳变"。

硬规则：

1. **写死、逐字一致**：共享物件/材质在**每个场景的提示词里各自写一份具体规格**（颜色/材质/五金/纹理），文字逐字一致。例：入户门统一写"深灰黑(#2A2A2A)系哑光深色金属门，单扇，配深灰色金属门把手、猫眼、金属门牌号，门扇表面哑光深色金属、无明显花纹"。
2. **禁止关系引用**：不要在提示词里写"本场景与『X场景』同属那套公寓""与Y场景为同一扇门"这类**依赖其他场景名的关系表述**——画图模型只看得到具体描述，关系引用无效。一致性靠**具体材质规格的一致文字**保证，不靠场景名关联。
3. **共享物即锚点**：跨场景出现的物件（门、窗、墙面、地板、家具）在 drama-episode-analyzer 的 design/description 阶段就标记为共享锚点，出图提示词以它为中心做材质锁定；多个场景共用同一段锚点规格文字。
4. **<LOCK> 补一条**：凡跨场景共享物件，<LOCK> 段追加一致性条款（仍写具体规格，不点名其他场景）——"本场景的X物件与同剧其他场景所见为同一物件/同一套装修，材质、颜色、五金、纹理完全一致"。

> 适用：同空间多场景（公寓走廊与室内）、同一物件多场景出现（入户门内外两面）、同户型多集复用。

## Automated Mode (Harness Integration)

当被 `ai-drama-harness` 调用时，额外输出结构化 JSON，供 harness 通过 `python cli.py write --table 场景库` 写入飞书。

每个场景输出一批 JSON（每个场景 1 个全景基准图）。

### 读取输入

```bash
python cli.py read $WS --table 剧本设定
python cli.py read $WS --table 场景库    # 读取已有场景（含 description 空间设计 + 绑定状态 + 已生成的基准图）
```

Step 1 校验场景库中每个待出图场景的 `description` 字段（由 drama-episode-analyzer 产出）。校验不通过则中止并报错。
