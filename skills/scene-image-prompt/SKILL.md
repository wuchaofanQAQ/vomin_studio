# Scene Image Prompt

## Overview

把剧本设定 + 分集里的场景描述，转成**可直接投喂豆包 seedream** 的场景空镜图提示词。每个视角独立一条提示词、独立一张图，纯空镜无角色。

**本 skill 是执行者**：需要出哪些场景、哪些视角由上游决定（storyboard-prompt 定义需求 → harness 差分比对 → 本 skill 执行出图提示词）。

支持的视角类型（按生成顺序）：
- **正视图（默认）**：所有场景必出，是后续视角的母版图
- **反打图**：对向反向平视回望，对话/对峙场景需要
- **45°俯视斜角**：俯瞰空间布局全貌
- **90°垂直俯视**：楼板拆掉后的户型图，镜头垂直向下

每个视角独立一条提示词，逐步生成、逐步确认。

## 空间规则

四个视角是同一套家具、同一时间、同一光线，只是机位不同。先锁定主轴：**P0** 是门洞，**P1** 是主窗或主背景墙，**M** 是主体。

- 家具位置用北/南/东/西写进 `<SPACE MAP>`，各视角共用，不写"摄影机身后""画面左侧"。
- 正视图：摄影机站在 P0 旁，面朝 P1。门洞在镜头后方，不入画。
- 反打图：摄影机站在 M 与 P1 之间的主轴上，面朝 P0。画面左侧是面朝 P1 时的右手侧墙，画面右侧是当时的左手侧墙。镜头后方不入画。母版没拍到的 P0 另一侧按文字生成，消失点是 P0。
- 画面左侧、画面右侧必须带墙名和物件。不写"左右互换"。

## Workflow

### Step 0 — 接收场景清单

harness 传入待出图的场景清单，每个场景含名称和需要的视角列表。例如：

```
待出图场景：
- 出租屋：正视图（默认）、反打图
- 写字楼大堂：正视图（默认）
- 停车场：正视图（默认）、反打图、45°俯视斜角
```

如果某场景的正视图已存在（场景库中已有），则只出缺失的视角。

### Step 1 — 读取空间设计（校验 description）

从场景库读取每个待出图场景的 `description` 字段。该字段由 `drama-episode-analyzer` 产出，已经是北/南/东/西。各视角的 `<SPACE MAP>` 直接复用，不改写物件位置和属性。

**校验规则**——逐条检查 description 是否包含：
- 【摄影主轴】含 P0、P1、M 三个锚点
- 【物件清单】至少列出 3 个物件及其方位
- 【光源】至少 1 个光源含位置和色温

**如果 description 为空或校验不通过**：报错并列出缺失项，不继续出图。harness 需先为该场景运行 `drama-episode-analyzer` 补充空间设计。

**如果校验通过**：将 description 加载为当前场景的空间锁定上下文，供 Step 2~5 组装 `<SPACE MAP>` 段。

### Step 2 — 正视图（默认视角/原图）

所有场景都需要此步骤。正视图是场景的**母版图**，后续所有视角图都以此为参考。

**画面要求：**
- 纯空镜，16:9 横版，无角色无文字
- 画框中要出现**主要活动区域**，需要包含**上下左右四面以及背景信息**
- 要有**纵深空间感**，便于后续模型通过该图生成反打图和俯视图
- 摄影机位于 P0 附近，面朝 P1，平视，展示空间全貌
- 所有物件的空间关系、门/窗朝向、光源位置必须精准锁定

**提示词组装：** 按 `references/prompt-blueprint.md` 写，顺序为 `<HEADER>` → `<STYLE LOCK>` → `<LOCK>` → `<SPACE MAP>` → `<CAMERA>` → `<QUALITY>`。每个视角一张图。

写完后核对 P0、P1、M、物件、门窗、光源与 description 一致。有缺失或和 `<CAMERA>` 矛盾就改完再输出。

输出提示词 + 说明（场景类型、P0→P1 主轴、光源位置、缺失项）+ 校验声明。

**单视图场景到此结束。** 多视图场景继续以下步骤，每步确认后再进入下一步。

### Step 3 — 反打图（如需）

参考 `{场景库：场景名·正视图（默认）}`。母版只提供已经入画家具的外形、材质和颜色。机位、左右和消失点按上面的空间规则写，模板见 `references/prompt-blueprint.md`。

### Step 4 — 45°俯视斜角全景（如需）

参考 `{场景库：场景名·正视图（默认）}` 作为场景母版。

**画面要求：**
- 生成同一场景的 **45° 俯视斜角全景**
- 摄影机在 M 上方、略偏 P0，向 P1 俯约 45°。画面下缘是 P0，上缘是 P1
- 要看到地面和家具的平面分布
- `<LOCK>` 用反打、45°、90° 那一版

**提示词结构：** 按 `references/prompt-blueprint.md` 的 45° 模板写。

### Step 5 — 90°垂直俯视上帝视角（如需）

组合参考三张图：
- `{场景库：场景名·正视图（默认）}` — 正面平视原图
- `{场景库：场景名·反打图}` — 反向平视图
- `{场景库：场景名·45°俯视斜角}` — 45° 俯视图

**画面要求：**
- 户型图。镜头在 M 正上方，垂直 90° 向下，像把楼板拆掉后拍摄
- 天花和楼板不入画。墙只是平面边界，家具是俯视轮廓
- 画面上缘是 P1，下缘是 P0。左缘是面朝 P1 时的左手侧墙，右缘是右手侧墙
- `<LOCK>` 用反打、45°、90° 那一版

**提示词结构：** 按 `references/prompt-blueprint.md` 的 90° 模板写。参考正视图、反打图、45° 俯视三张图。

## Automated Mode (Harness Integration)

当被 `ai-drama-harness` 调用时，额外输出结构化 JSON，供 harness 通过 `python cli.py write --table 场景库` 写入飞书。

**每个步骤独立输出一批 JSON**（不是一次性输出所有视角），用户确认当前步骤并生成图片后，再进入下一步骤。

### 读取输入

```bash
python cli.py read $WS --table 剧本设定
python cli.py read $WS --table 场景库    # 读取已有场景（含 description 空间设计 + 已生成的视角图）
```

Step 1 校验场景库中每个待出图场景的 `description` 字段（由 drama-episode-analyzer 产出）。校验不通过则中止并报错。

### Step 2 输出 — 正视图 JSON

````
```json:structured-output
[
  {
    "name": "写字楼大堂",
    "view_angle": "正视图（默认）",
    "description": "【场景基础】室内·现代写字楼一层大堂，当代商务风，日间自然光，大理石地面+玻璃幕墙\n【功能区】A区=前台接待（中轴）B区=等候休息（东墙，面朝P1时的左手侧墙）C区=电梯厅（南墙，P1）\n【摄影主轴】P0=旋转门（北侧） → P1=电梯厅背景墙（南墙） M=圆形前台。轴线从北指向南。面朝 P1 时，左手侧墙是东墙，右手侧墙是西墙\n【物件清单】圆形前台：A区，中轴，正面朝北；皮质沙发组：B区，东墙落地窗前；大理石立柱×2：主轴东西两侧；绿植盆栽：前台南侧；旋转门：北侧，正视图不入画\n【门窗】旋转门：北侧，朝外，正视图不入画；落地玻璃幕墙：东墙整面，朝东\n【光源】落地幕墙（主光）：东墙，自然光，日间白光，从东向西照亮前台与等候区；顶部筒灯×8：均匀分布，人造光，暖白3500K，补充中央区域照明",
````

````
```json:structured-output
[

    "name": "写字楼大堂",
    "view_angle": "反打图",
    "gen_prompt": "参考{场景库：写字楼大堂·正视图（默认）}为场景母版...",
````
