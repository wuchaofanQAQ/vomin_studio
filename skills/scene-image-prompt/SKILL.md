# Scene Image Prompt

## Overview

把剧本设定 + 分集里的场景描述，转成**一条可直接投喂豆包 seedream** 的场景空镜图提示词。场景是**单张 3×3 九宫格多机位场景板、纯空镜、无角色**，专为"后续把角色/人物叠加进去"预留空间。

## 九宫格核心纪律（最高优先级）

一张九宫格图 **不是九个不同场景，也不是九种重新设计**，而是：

- **同一个空间、同一套建筑结构、同一套家具 / 道具、同一时间、同一光线条件**，由摄影机移动到九个不同位置进行拍摄。
- **摄影机可以移动，环境不允许改变；所有锁定关系不允许改变**（空间结构、家具摆放、门窗朝向、材质、色调、光源全部锁定）。

提示词必须逐字写清这两条，缺一不可。

## 锚点关系完全对应纪律（最高优先级）

- **锚点关系必须做到非常细节**：画面中出现的**每一个物件**（沙发、餐桌、入户门、窗户、柜体、床、书桌、厨房台面、灯、装饰物等）都必须写入它的对应关系——它在哪个区域、相对哪些物件在什么方位、朝向如何。
- **最终提示词产出的空间关系必须与锁定关系完全对应**：提示词写完后，逐项回查锁定关系清单，任何一项物品的位置/朝向/门开向/窗朝向在提示词中缺失、含糊、或与其他面板描述矛盾，**该提示词即为错误**，必须修正后才能输出。

## 机位双锚点纪律（最高优先级）

- **只写"左前方 / 右前方 / 左侧 / 右侧 / 深处 / 正面"这类没有参照物的裸方位词，机位等于没写**——"左"是相对谁、"前方"是站在哪里看，模型无从判断，此类描述一律禁止。
- `<SPACE MAP>` 必须先锁定一条**摄影主轴**，作为全部分区方位与机位方位的**唯一参照系**：写明主轴**站位端锚点 P0**（通常是主入口 / 门洞 / 摄影机起点）、主轴**朝向端锚点 P1**（通常是主背景墙 / 主窗）、**主体锚点 M**（场景中心主体）；此后一切"正面 / 左侧 / 右侧 / 前方 / 后方"均以"**摄影机站在 P0、面朝 P1**"为基准，不允许出现第二种基准。
- `<PANELS>` 中**每一个机位**都必须写全以下要素，缺一不可：
  1. **站位区域**：摄影机位于 A / B / C 哪个区域；
  2. **站位锚点**：摄影机紧靠 / 背靠 / 位于哪个已锁定的具体物件或建筑构件旁（必须是 `<SPACE MAP>` 中已命名的实体，如"紧靠原木餐桌靠门洞一侧的桌角"），禁止只写"在左前方"；
  3. **朝向区域**：镜头指向哪个区域；
  4. **朝向锚点**：光轴对准哪个已锁定实体（如"光轴对准布艺沙发正面与南墙大窗"），并写清该画面的**前景 / 中景 / 背景各是什么锚点**；
  5. 机位高度、镜头焦段照原规则写。
- 机位之间的对称 / 反打关系也必须用锚点表达，禁止用"对面""反方向"一笔带过：例如⑥是⑤的反打，则⑥的**站位锚点 ≈ ⑤的朝向锚点**、⑥的**朝向锚点 = ⑤的站位锚点**。
- 组装完成后逐机位回查：任何机位只给方位没给锚点、锚点在 `<SPACE MAP>` 中不存在、或与空间地图矛盾，**该提示词即为错误**。

## Workflow

### Step 1 — 抽取场景要素

从剧本设定 + 分集场景描述中抽取（缺失项标"未指定"，不臆造）：

1. **场景类型**：室内/室外、具体地点（客厅/玄关/办公室/废墟/古战场…）
2. **时代/风格**：从剧本设定继承
3. **主体物**：场景中心主体（沙发/餐桌/柜台/装置…）
4. **空间锚点**：核心区域划分（A 区/B 区/C 区）、左/右/前/后/中央各有什么固定物；并确定**摄影主轴（机位方位的唯一参照系）**：站位端锚点 P0（通常为主入口/门洞）、朝向端锚点 P1（通常为主背景墙/主窗）、主体锚点 M（场景中心主体）；九宫格所有"左/右/前/后"均以"站在 P0、面朝 P1"为基准，P0 左手侧、右手侧分别对应哪些区域也要写明
5. **门/窗朝向**：每个门、每扇窗的朝向与相对位置（如"入户门在画面右侧，门扇朝内开；客厅大窗在正对沙发的南墙"）
6. **光源位置（★必抽）**：光源数量、每个光源的位置（如"客厅大窗在沙发正对墙，傍晚暖光从窗外照入"）、光源类型（自然光/灯）、色温（暖/冷）、照射方向、光线对哪些主要物件形成高光/阴影
7. **环境氛围**：光线（日/夜/黄昏）、天气、色调
8. **材质体系**：墙面/地面/家具/核心装饰材质

### Step 2 — 组装九宫格场景提示词

用 `references/prompt-blueprint.md` 模板，按固定段落顺序组装单条 prompt。核心规则：

- **16:9 横版**、单张、**3×3 九宫格**、白色间隙分隔、纯空镜无角色
- **一致性总锁定**：同一空间/同一建筑结构/同一套家具道具/同一时间/同一光线；摄影机可移动、环境不允许改变、所有锁定关系不允许改变
- **九宫格机位（★双锚点强制）**：按固定 ①~⑨ 九个机位逐一描述（见 prompt-blueprint.md）；每个机位必须写全"站位区域 + 站位锚点（紧靠什么已锁定实体）→ 朝向区域 + 朝向锚点（光轴对准什么实体）+ 前景/中景/背景锚点"，禁止"左前方/深处"等无参照裸方位词
- **空间关系描述（★必须极致细节）**：所有画面出现的物品/区域（沙发、餐桌、入户门、窗户、柜体等）的**对应位置关系**必须逐一精准文字写出；每个门的朝向、每扇窗的朝向必须写明；光源位置必须写入并与其他物件的光照关系对应；`<SPACE MAP>` 必须先写摄影主轴（P0/P1/M），作为所有方位与机位的唯一参照系
- **完全对应校验（★必须执行）**：组装完成后，将产出提示词逐项回查 Step 1 的锁定清单（物品位置/门开向/窗朝向/光源位置/**每机位的站位锚点与朝向锚点**），有一项缺失、含糊或矛盾即视为错误提示词，修正后重新输出
- **无人物、无文字**；如需画面有文字用中文引号标注
- 画风从剧本设定继承（`references/scene-lexicon.md`）

### Step 3 — 输出与说明

输出提示词，附 2–3 行说明：场景类型、核心空间锚点与摄影主轴（P0→P1、主体 M）、门/窗朝向、光源位置如何确定、哪些项未指定。**附一句完全对应校验声明**：如"已逐项核对：沙发/餐桌/入户门/窗/光源位置与锁定清单完全对应；九个机位的站位锚点与朝向锚点均取自 SPACE MAP 且无矛盾"。用户修正 → 更新对应段落重出整条 prompt。

## Automated Mode (Harness Integration)

当被 `ai-drama-harness` 调用时，额外输出结构化 JSON，供 harness 通过 `python cli.py write --table 场景库` 写入飞书。

### 读取输入

```bash
python cli.py read $WS --table 剧本设定
```

### JSON 输出格式

````
```json:structured-output
[
  {
    "name": "写字楼大堂",
    "description": "现代化写字楼一层大堂，大理石地面...",
    "gen_prompt": "16:9横版3×3九宫格，现代写字楼大堂...",
    "source": "AIGC生成"
  }
]
```
````

harness 写入后通过 `python cli.py generate $WS --target 场景库:写字楼大堂` 触发出图。
