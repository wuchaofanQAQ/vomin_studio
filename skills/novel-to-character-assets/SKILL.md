# Novel To Character Assets — 小说抽取角色资产

## Overview

Phase B 逐集流程 **B0b 的角色部分**。在 `novel-to-script` 把本章写入剧本表之后，通读**当前章小说原文**（`小说内容`），识别角色库中尚未收录的新角色，为每个新角色产出完整 6 模块角色档案：

```
剧本表·小说内容（第 N 集对应章节）+ 角色库
  （无小说原文时退回 完整剧本）
  → 新角色清单
  → 角色库（精简版，供生图/TTS） + 角色档案（完整 6 模块，供编剧/分镜/战斗）
```

> 本 skill **只抽取角色**，不读写场景库；场景抽取与空间设计由 `script-to-scene-assets` 负责。

**幂等规则**：已在角色库中的角色自动跳过，不重复抽取。

## 核心纪律

- **以小说原文为准**：角色的外貌、性格、身份、标志性特征优先取自小说原文（转剧本时这些细节会被压缩丢失）；小说没写的才看剧本，剧本也没有的标"未指定"，不凭空臆造。
- **缺失项标"未指定"**：原文未描述的细节标注"未指定"，不替作者脑补。
- **画风继承剧本设定**：角色风格从剧本设定的画面风格字段继承，不自行发明。
- **只分析不写入**：产出草案后由 harness 展示确认清单，确认后才 write。

## Workflow

### Step 0 — 加载上下文（只读，无需确认）

```bash
python cli.py read $WS --table 剧本表 --episode N --with-novel   # 仅当前章：取 小说内容（原文）+ 完整剧本
python cli.py read $WS --table 剧本设定                            # 画风/世界观
python cli.py read $WS --table 角色库                              # 检查已有角色
```

- **只读当前集，不加 `--context`**：带 `--with-novel` 时前后章原文会撑爆上下文；跨集别名/延续问题靠角色库已有角色与"首现版为准"规则处理。
- `小说内容` 为空（用户直接上传成品剧本）→ 退回用 `完整剧本` 抽取，档案里剧本没写的项照旧标"未指定"，`notes` 注明"来源：剧本，无小说原文"。

### Step 1 — 新角色识别与档案产出

扫描当前章小说原文中出现的所有命名角色（含有台词或动作的角色），与角色库对比：
- 已在角色库 → 跳过
- 不在角色库 → 产出完整角色档案（双表结构）：

**角色库（精简版，供生图/TTS）**：
- `name`：角色名
- `char_type`：核心/配角/路人
- `appearance`：外貌一句话摘要（喂给三视图）

**角色档案（完整 6 模块 A–F，供编剧/分镜/战斗）**：按 `references/bible-template.md` 的 A–F 模块逐字段抽取：
- `basic_info`(A)：角色名、定位、出场集数、身份、性别、关系
- `style_desc`(B)：画风基调（继承剧本设定）、主色调、整体气质
- `voice_desc`(C)：音色、语速语气、口音
- `appearance`(D)：脸部细节、身体、服装配饰、标志性特征
- `personality`(E)：性格、动机、弱点、说话风格
- `battle_desc`(F)：战斗风格、招式、阶段状态、特效

> 经典动作/口头禅、来源与缺失项不落表——飞书角色档案已删除「标志性表达」「标注交接」两个字段；这些分析结论只写进给用户看的说明里。

**抽取规则**（详见 `references/role-extraction.md`）：
- 缺失项标"未指定"，不臆造
- 小说里的外貌、服装、年龄、口音、性格描写尽量逐项落到对应字段；标志性特征（伤疤/纹身/道具）是一致性锚点，必须完整保留
- 小说用比喻/抽象形容的外貌，转成可出图的具体描述，原句留在 `notes`
- 画风基调从剧本设定继承
- `notes` 记录来源：小说第 N 章 / 剧本
- 多集描述冲突时以首现版为准，标注冲突

### Step 2 — 输出

产出人类可读摘要 + 结构化 JSON。摘要包含：
- 新角色列表（如有），每人一句话概述
- 复用的已有角色
- 缺失项/不确定项汇总

## Automated Mode (Harness Integration)

当被 `ai-drama-harness` 调用时，额外输出结构化 JSON：

````
```json:structured-output
{
  "new_characters": {
    "角色库": [
      {
        "name": "保镖甲",
        "char_type": "路人",
        "appearance": "高大壮硕，黑色西装，寸头，国字脸"
      }
    ],
    "角色档案": [
      {
        "name": "保镖甲",
        "char_type": "路人",
        "basic_info": "角色名：保镖甲\n定位：龙套\n出场集数：第3集\n身份：赵总私人保镖\n性别：男\n关系：赵总的手下",
        "style_desc": "画风基调：电影级写实\n主色调倾向：黑灰\n整体气质：威压",
        "voice_desc": "成年男，低沉粗犷",
        "appearance": "脸型：国字脸\n头发：寸头黑发\n五官：未指定\n肤色：小麦色\n体型：高大壮硕\n服装：黑色西装、黑色皮鞋\n标志性特征：未指定",
        "personality": "性格：沉默寡言\n动机：听从赵总指令\n说话风格：简短命令式",
        "battle_desc": "战斗风格：未指定"
      }
    ]
  },
  "skipped_characters": ["张三", "李四"]
}
```
````

harness 收到后：
1. 展示新角色列表（含档案摘要），请求确认
2. 确认后写入角色库 + 角色档案（完整 6 模块，无需额外深化）：
   ```bash
   python cli.py write $WS --table 角色库 --data '<new_characters.角色库>'
   python cli.py write $WS --table 角色档案 --data '<new_characters.角色档案>'
   ```
3. 后续由 `character-three-view-prompt` 出三视图；场景部分由 `script-to-scene-assets` 处理
