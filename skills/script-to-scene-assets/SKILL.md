# 剧本 → 场景图抽取（script-to-scene-assets）

## Overview

Phase B 逐集流程的 **B0b**：在 `novel-to-script` 把本集剧本写入剧本表之后、`director-segment-prompt` 拆分镜之前运行。

```
剧本表·完整剧本（第 N 集，定场景清单/名称/时段）
  + 剧本表·小说内容（第 N 集对应章节，补空间细节；为空则只用剧本）
  → 场景清单 / 图间关联表 / 空间锚点表          （对话中展示，供确认）
  → 场景库行：视角 + 描述 + 参考场景 + 作用关联 + 生成提示词
  → （确认后）generate 出图 → 一致性检查 → 放行进入分镜
```

目标不是画"漂亮插画"，而是产出**可复用、可对齐、可挂参考、关系可追溯**的场景资产。

本技能取代两处旧职责：旧版 `drama-episode-analyzer`（现已改为 `novel-to-character-assets`，仅负责从小说抽取角色）的场景抽取与空间设计、`scene-image-prompt` 的提示词组装。

## 核心原则

1. **先总后分**：先定总空间母版，再派生主场景图和局部图，禁止各局部空间独立自由生成。
2. **每张图必须标注作用**：这张图干什么用、给谁挂参考、不用于什么。
3. **图间关联必须写清楚**：母版→派生、主图→局部、参考图→生成片段，不能只列图不列关系。
4. **场景图不是剧照**：无人、无剧情动作、无文字，只定义空间结构、光线、色调、关键陈设。
5. **锚点优先于形容词**：入口位置、地面材质与分界、主要功能区方位、门窗方位、光源方向，逐条写死。
6. **一致性靠约束，不靠运气**：每张派生图重复母版锚点，出图后人工比对硬指标。
7. **场景图分三层**：母版图 → 主场景图 → 局部补充图。分镜关键帧不属于场景资产。
8. **独立生成 ≠ 独立定义**：母版可单独抽一张图，但生成时就要带上派生图的关键锚点。
9. **剧本定"有哪些场景"，小说补"场景长什么样"**：场景清单、名称、时间段、哪场戏发生在哪里以剧本为准；空间结构从角色动作中发现（开门、坐沙发、看窗外），再用当前章小说原文补布局、材质、陈设、光线、气味氛围等被剧本压缩掉的细节。两者都没写的标"未指定"，不凭空臆造。
10. **画风与画幅继承剧本设定**：画风取"画面风格"，画幅取"平台调性"，不自行发明。

## 持久主键与命名（★ 必读）

场景库的行主键是 **`name` + `view_angle`**，下游全部按它引用。本批内部的 `S00/S01…` 编号只用于对话中对表，**不写入飞书**。

| 字段 | 取值 |
|---|---|
| `name` | **空间名**。同一空间的母版/主图/局部共用同一个 `name`。**不得含 `·`**（`·` 是 name 与视角的分隔符，含它会让引用解析错位） |
| `view_angle` | `母版` / `主场景` / `局部·厨房`（局部后接具体部位）/ `闪回` / `外景` |

光影不同的同一空间用**全角括号**区分名字：`出租屋（夜）`、`出租屋（日）`；同空间只出现一种光影时不加后缀。

引用写法（出现在提示词里）：
- `{场景库：出租屋（夜）}` → 裸名，默认取**主场景**（没有主场景时依次回退到全景基准图/其他非母版/母版）
- `{场景库：出租屋（夜）·母版}` / `{场景库：出租屋（夜）·局部·厨房}` → 显式指定视角

**母版不直接挂分镜**，所以分镜里一律写裸名或显式写主场景/局部，不引用母版。

## Workflow

### Step 0 — 加载上下文（只读，无需确认）

设当前集为 N：

```bash
python cli.py read $WS --table 剧本表 --episode N --context 1   # N-1/N/N+1 的 script（不含小说原文，仅用于跨集空间延续）
python cli.py read $WS --table 剧本表 --episode N --with-novel   # 仅当前集：取 小说内容（原文）补空间细节
python cli.py read $WS --table 剧本设定                          # 画风 / 平台调性（画幅）
python cli.py read $WS --table 场景库                            # 已有空间、母版、主图、局部
```

- 本集抽取只针对第 N 集；N±1 集仅用于判断空间是否跨集延续（如上集结尾在走廊，本集开头继续）
- **`--with-novel` 只用于当前集 N，不与 `--context` 同用**：带上前后章原文会撑爆上下文
- `小说内容` 为空（用户直接上传成品剧本）→ 只用剧本，空间细节缺的照旧标"未指定"

**幂等与复用**（逐集增量的核心）：
- 场景库已有该空间的**母版** → 不重建母版，只判断是否需要追加主场景/局部
- 已有主场景/局部且覆盖本集所需视角 → 复用，列入 `reused`
- 本集出现新空间 → 新建（按下方判断是否需要母版）
- 已有空间但本集需要新局部 → 只追加局部行，并写明与已有主场景的咬合关系

### Step 1 — 读取剧本提取场景，用小说原文补细节

逐场扫描 `script` 的结构化场头，按以下字段提取：

| 字段 | 说明 |
|---|---|
| 场号 | 剧本中的场次编号 |
| 内/外景 | INT / EXT |
| 地点 | 剧本中标注的空间名称 |
| 时间 | 日 / 夜 / 黄昏等 |
| 出场人物 | 本场人物正名 |
| 关键动作 | 决定场景里需要哪些陈设和站位空间 |
| 色调/特殊要求 | 如闪回低饱和、外景强光热浪等 |

**合并规则**：同一地点、同一时间、同一空间逻辑的场，合并为一个场景。

**拆分规则**：
1. **空间连通性**：被实体墙或门隔开的区域是不同空间（客厅 / 卧室）；互通的是同一空间（客厅与开放式厨房）。封闭式厨房有墙/门阻隔 → 独立空间。
2. **光影时刻**：同一空间不同时刻/光影拆为不同场景，名字体现（`出租屋（夜）` / `出租屋（日）`），各自有自己的母版或主图。
3. **闪回、不同时间、不同地点、明显不同光线**：必须独立场景。

> 先按规则 1 定"空间"，再按规则 2 定"光影行"。一个空间 × 一个光影时段 = 一个场景。

**小说原文的使用边界**（场景清单定完后，再对每个场景回小说找细节）：

1. **可补**：房间布局与方位、地面/墙面/家具材质与颜色、固定陈设、门窗位置、光源与天气、环境氛围，写入空间锚点表与 `description`，并在 `notes` 标"来源：小说第 N 章"。
2. **不新增场景**：小说里提到、但剧本本集没有出现的空间，不建场景行。
3. **冲突以剧本为准**：场景名、时间段、场次归属、角色在场景里的动作以剧本为准；小说细节与剧本动作矛盾时（如小说写"靠窗沙发"，剧本里角色坐在门边），按剧本，并在不确定项里提示。
4. **比喻转具体**：小说用比喻/情绪化形容的空间（"像牢笼一样的屋子"），转成可出图的具体陈设与尺度，原句不进提示词。
5. **不把剧情写进场景图**：小说里的人物、动作、事件描写一律过滤，场景图仍是无人空间。

### Step 2 — 输出场景清单

每张图必须写清三件事：作用、关联、不用于什么。

| 场景ID | 对应场号 | 场景（name） | 视角（view_angle） | 类型 | 作用 | 关联 | 不用于 |
|---|---|---|---|---|---|---|---|
| S00 | 全局/多场 | 出租屋（夜） | 母版 | 母版 | 定义整套空间骨架；给派生图做参考 | 派生 S01、S02…；约束入口、地面、功能区、门窗、光源 | 不直接挂分镜生成 |
| S01 | 场1、场3 | 出租屋（夜） | 主场景 | 主场景 | 场1/场3 生成片段挂参考 | 继承 S00；与 S02 咬合 | 不用于局部特写 |
| S02 | 场3 | 出租屋（夜） | 局部·厨房 | 局部补充 | 场3 厨房动作片段挂参考 | 继承 S00/S01；与 S01 咬合 | 不用于主场景全景 |
| S03 | 场5 | 旧出租屋 | 闪回 | 闪回/特殊 | 场5 闪回片段挂参考 | 独立空间；仅色调统一 | 不用于现实时空 |

作用标注要求：
- **母版**：写"给谁做派生参考、约束哪些锚点、不直接挂分镜"
- **主场景**：写"哪些场号/生成片段挂它、继承哪张母版、与哪张图共享什么关系"
- **局部补充**：写"补哪个具体镜头、必须和哪张主图咬合、不用于什么"
- **闪回/特殊**：写"独立原因、仅统一什么"

**判断是否需要母版**：同一套空间出现两个以上相连区域（主空间+子空间、室内+入口）→ 需要母版；单一独立空间 → 跳过母版，直接做主场景（此时主场景自带完整锚点）。

### Step 3 — 输出图间关联表

单独输出，把"谁派生谁、谁约束谁、谁和谁必须咬合"写清楚。

| 源图 | 目标图 | 关联类型 | 必须继承/约束的内容 | 检查方式 |
|---|---|---|---|---|
| S00 | S01 | 派生 | 入口位置、地面材质与分界、主要功能区方位、门窗方位、光源方向 | 硬指标比对 |
| S00 | S02 | 派生 | 入口位置、地面材质、局部与主空间的连接关系 | 硬指标比对 |
| S01 | S02 | 咬合 | 局部图可见的主空间元素必须与主场景图一致；连接开口方向一致 | 人工比对连接处 |
| S01 | S04 | 共享锚点 | 共享同一扇门/窗/外墙，写清共享元素 | 比对共享元素 |
| S03 | 无 | 独立 | 特殊时空独立，不与现实空间共用锚点；仅统一指定色调 | 色调检查 |

| 关联类型 | 含义 | 写法要求 |
|---|---|---|
| 派生 | 目标图从源图生成或参考源图 | 写清"必须继承哪些锚点" |
| 咬合 | 两张图必须能拼在同一空间里 | 写清"哪一侧对哪一侧、哪个开口对哪个开口" |
| 共享锚点 | 两张图不直接派生，但共享同一空间元素 | 写清"共享的是门、窗、地面还是光源" |
| 独立 | 不与其它图共用空间锚点 | 写清"独立原因"和"仅统一什么" |

落库映射：每个目标图一行，源图列表写进该行 `ref_scenes`（如 `出租屋（夜）·母版`），关联类型与继承内容写进 `relation_note`。

### Step 4 — 写空间锚点表

只对需要一致性的空间写。锚点按项目实际填写，不预设空间类型。

| 锚点 | 定义 | 约束 | 涉及图 |
|---|---|---|---|
| 入口/出入口 | 位置、开门方向、门框特征 | 相关图必须同一入口、同一方向 | 列出涉及图 ID |
| 地面材质与分界 | 材质、颜色、高低差、分界线 | 相关图材质和分界一致 | 列出涉及图 ID |
| 主要功能区方位 | 如操作区、休息区、通道 | 左右/前后关系不反转 | 列出涉及图 ID |
| 门窗方位 | 窗、内门、通道开口 | 所有视角方向一致 | 列出涉及图 ID |
| 固定家具/陈设 | 影响空间关系的关键物件 | 位置固定 | 列出涉及图 ID |
| 主光源 | 主光从哪来、明暗关系 | 相关图光源方向一致 | 列出涉及图 ID |
| 色调 | 整体色温、氛围 | 同组场景统一 | 列出涉及图 ID |

每行"涉及图"必须写全，方便检查哪张图漏了哪个锚点。

**方位写法**：用北/南/东/西描述墙与物件（世界坐标，不随机位改变），并给出摄影主轴 P0（站位端锚点）→ P1（朝向端锚点）、M（主体锚点），以及"面朝 P1 时左手侧墙/右手侧墙是哪面"。详见 `references/camera-and-style.md`。

**跨场景共享锚点**：多个场景共享同一空间/物件（同一公寓的走廊与室内、同一扇入户门内外两面）时，各场景的描述对共享部分写**逐字一致的具体规格**（颜色/材质/五金/纹理），**禁止**写"与X场景同属一套"这类关系引用——画图模型只看得到具体描述。

### Step 5 — 生成场景图提示词包

按 `references/prompt-templates.md` 的**七段结构**写，母版、主场景、局部、闪回、外景各用对应模板：

① 作用标注 → ② 图的性质 → ③ 关联声明 → ④ 空间锚点 → ⑤ 光线与色调 → ⑥ 排除项 → ⑦ 参考图句

- 提示词写入场景库 `gen_prompt`；空间设计与锚点摘要写入 `description`
- 负向提示单独统一放在提示词包末尾，不逐条重复
- 画风取剧本设定"画面风格"，画幅取"平台调性"（竖屏短剧通常 9:16），见 `references/camera-and-style.md`

### Step 6 — 图生图参考句

派生图用场景引用语法挂参考图，由 `expand_prompt` 在展开时收集母版/主图图片：

> `{场景库：出租屋（夜）·母版} 图1：出租屋（夜）空间母版。保持参考图中的入口位置、地面材质与分界、功能区方位、门窗方位、光源方向不变，只改变视角和取景范围。`

- 展开时 `{…}` 标记会从正文移除，其图片作为参考素材传给出图 API；其后的文字保留，所以**参考句要在标记之外自成完整句子**
- "保持什么不变"比"画什么"更重要
- 派生图写清继承哪张图、继承哪些锚点；咬合图写清和哪张图对哪一侧、哪个开口对哪个开口

### Step 7 — 一致性检查（出图后门禁）

每张派生图生成后，人工比对硬指标，在报告中标注涉及哪几张图。

| 检查项 | 通过标准 | 不通过处理 |
|---|---|---|
| 入口位置和开门方向 | 相关图看到的是同一入口、同一方向 | 重抽，不将就 |
| 地面材质与分界 | 材质、颜色、分界线一致 | 重抽或局部重绘 |
| 主要功能区和门窗方位 | 左右/前后关系不反转 | 重抽 |
| 光源方向 | 主光方向一致 | 调整提示词重抽 |
| 色调统一 | 同组场景统一；特殊时空按设定统一 | 调色或重抽 |

**任一条不通过，停止后续片段生成，先修场景图。** 硬指标全过，才允许进入分镜的视频生成（确认点 3 之后）。检查表见 `references/consistency-check.md`。

## 输出格式

对话中交付（缺一不可）：

1. 场景清单表（含"作用""关联""不用于"三列）
2. 图间关联表
3. 空间锚点表（含"涉及图"列）
4. 场景图提示词包（每张开头标【作用】【关联】，末尾标参考图句，包末统一负向）
5. 复用清单（本集复用了库里哪些空间/母版/主图）
6. 使用说明：每个场景对应哪些场号、哪些生成片段挂哪张图、哪张图不能直接用于什么
7. 缺失项/不确定项（剧本没写、标"未指定"的空间细节）

出图后另补：一致性检查报告（逐图打勾，标注涉及图）。

````
```json:structured-output
{
  "场景库": [
    {
````

### 确认后的写入与生成（harness 执行，每步均需用户确认）

1. 写入场景库（文字资产，不出图）：
   ```bash
   python cli.py write $WS --table 场景库 --data '<场景库部分>'
   ```
2. 出图（花预算，清单须列对象与预估花费）。**同一空间命中多行时，`generate` 自动按 母版 → 主场景 → 局部 → 其他 的顺序出图**，保证派生图生成时母版已就绪：
   ```bash
   python cli.py generate $WS --target 场景库:出租屋（夜）
   # 或只出某一张
   python cli.py generate $WS --target 场景库:出租屋（夜）·主场景
   ```
3. 一致性检查通过后，场景图才可被 director-segment-prompt 的分镜引用。

**懒加载**：本技能只建场景文字资产与提示词；harness 在 director-segment-prompt 产出本集场景依赖清单后，再只为本集用到的场景出图。出图时，被依赖的主场景/局部所依赖的母版一并出图。

## 与旧模型的兼容

场景库里存量的 `view_angle=全景基准图（默认）` 行仍然有效：裸名引用的回退顺序是 主场景 → 全景基准图 → 正视图 → 其他非母版 → 母版，旧行无需迁移即可被分镜引用。新增的空间一律按本技能的视角取值。

## 常见错误清单

| 错误 | 后果 | 修正 |
|---|---|---|
| 只列场景清单，不写图间关联 | 后面不知道哪张挂哪张、谁派生谁 | 必须输出图间关联表 |
| 图只写"主场景/局部"，不写作用 | 误用，拿局部图生成主场景全景 | 每张图标"作用/不用于" |
| 主场景和局部各自独立抽图 | 入口、地面、方位对不上 | 先抽母版，再派生，关联表写清咬合关系 |
| 提示词只写氛围形容词 | AI 自由发挥，空间乱 | 逐条写锚点，锚点表标涉及图 |
| 场景图里有人物正脸 | 后续挂参考图冲突 | 强调无人、无正脸 |
| 手机/屏幕字让 AI 生成 | 乱码 | 屏幕留白，后期贴字 |
| 闪回不单独定义色调 | 现实与特殊时空混色 | 独立场景 + 专用色调提示 + 关联表标"独立" |
| 局部图不写"从哪看向哪" | 方向和主图相反 | 写死画面左右关系 + 咬合对象 |
| 一条不过就继续生成 | 后面全歪 | 硬指标全过再继续 |
| 场景名里带 `·` | 与"名·视角"分隔符冲突，引用解析错位 | 光影变体用全角括号 `出租屋（夜）` |
| 参考句写成"参考图：{…}。保持…" 且标记后无完整句 | 展开移除标记后句子残缺 | 标记之外自成完整句，见 Step 6 |

## 自检清单

### 场景资产自检

| 检查项 | 通过标准 |
|---|---|
| 场景清单 | 每个场景有 ID、场号、类型、作用、关联、不用于 |
| 图间关联 | 派生、咬合、共享锚点、独立四种关系写清楚 |
| 空间锚点 | 入口、地面、功能区、门窗、固定陈设、光源逐条写死，标明涉及图 |
| 母版 | 复杂空间先抽母版，母版提示词已含派生图锚点 |
| 复用 | 库里已有的空间/母版/主图已复用，未重复创建 |
| 命名 | `name` 不含 `·`；`view_angle` 取值合规；光影变体用全角括号 |
| 小说补充 | 只补当前集已有场景的空间细节；未新增场景；与剧本冲突处以剧本为准；比喻已转具体；无人物剧情混入；`notes` 标明来源 |
| 一致性 | 硬指标逐图比对，不通过不继续 |

### 提示词自检

| 检查项 | 通过标准 |
|---|---|
| ① 作用 | 写了用途、挂哪些场号、不用于什么 |
| ② 性质 | 写了"空间参考图/无人/视角/景别" |
| ③ 关联 | 写了继承谁、咬合谁、共享什么、是否独立 |
| ④ 锚点 | 入口、地面、功能区、门窗、固定陈设、通道逐条写死，左右方位明确 |
| ⑤ 光线色调 | 主光方向、明暗、色温、氛围都写了 |
| ⑥ 排除 | 无人物、无文字、无 logo、无水印、不要什么 |
| ⑦ 参考图 | 派生图写了挂哪张、保持什么、只改变什么 |
| 负向 | 包末统一负向已附 |
| 变量 | 项目名、图 ID、锚点已替换，没有残留占位符 |

七项缺一项，提示词不算完成。

## 一句话执行准则

先读剧本列场景，每张图标清作用和不用于什么；复杂空间先抽母版，母版、主图、局部图之间用关联表写清派生、咬合、共享锚点、独立四种关系；每条提示词按"作用 → 性质 → 关联 → 锚点 → 光线色调 → 排除 → 参考图"七段写死；每张图无人、无字、写死入口地面和光源；逐集增量、已有则复用；硬指标不过，不进入分镜生成。
