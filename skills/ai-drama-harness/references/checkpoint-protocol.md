# 确认点标准流程 + 写入授权状态机

> 本文件是 SKILL.md「写入授权铁律」的执行细则。**铁律优先于一切历史习惯：聊天不触发写入，每次写入飞书都必须在当次拿到用户明确确认。**

## 一、状态机

```
                    启动
                     │
                     ▼
              ┌─────────────┐  只读操作（read/pull/status/expand）
              │   沟通态     │◄──────────────┐  随时可做，不改变状态
              │ （默认状态）  │               │
              └──────┬──────┘               │
                     │ 草案完成，列出写入清单  │
                     ▼                       │
              ┌─────────────┐               │
              │  待确认态    │               │
              └──────┬──────┘               │
        ┌────────────┼───────────────┐      │
   "确认/写入/执行"  │ "修改：意见"   │ "重做" │
        │           ▼               │      │
        │    ┌─────────────┐        │      │
        │    │ 沟通态：只改  │────────┴──────┘
        │    │ 草案不写入    │ 旧授权作废，改完重新列清单
        ▼    └─────────────┘
 ┌─────────────┐
 │ 执行写入清单 │  init/write/generate/push
 └──────┬──────┘
        │ 执行完毕
        ▼
   回到沟通态（下一批写入需重新确认）
```

## 二、什么算"只读"，什么算"写入"

| 类别 | 命令/动作 | 是否需要确认 |
|---|---|---|
| 只读 | `read` / `pull` / `status` / `expand` | 否，随时执行 |
| 只读 | 调用 skill 产出文字草案、回答问题、展示方案 | 否 |
| 写入 | `init`（建表/建 workspace） | **每次必须确认** |
| 写入 | `write`（任何表的新增/更新） | **每次必须确认** |
| 写入/消费 | `generate`（出图/视频/配音，花预算） | **每次必须确认** |
| 写入 | `push`（本地数据同步到飞书） | **每次必须确认** |
| 写入 | 返工后重新生成 | **每次必须确认** |

## 三、确认点一览（4 个，与 SKILL.md 一致）

| # | 标题 | Phase | 确认方式 | 写入清单内容 |
|---|---|---|---|---|
| 1 | 剧本初始化 | A1 | 对话确认 | init（模式B）+ write 剧本设定/角色库/角色档案 |
| 2 | 角色形象 | A2 | 飞书审核 | 写 gen_prompt + generate 角色三视图 |
| 3 | 分镜与视频提示词（逐集） | B1 | 对话确认 | 补缺失资产（场景/角色）+ write 剧本分镜表（一段一行）+ generate 配音/视频 |
| 4 | 视频成片（逐集） | B2 | 飞书审核 | 返工重生成（如有） |

> B1 由 `director-segment-prompt` 产出分段提示词；确认点 3 的清单须额外列明：段数、各段时长、总秒数/预估花费（按各段 timeline 真实秒数）、`expand --shot` 预检结果、待补/已就绪资产。

> **轻量确认（不计入上表、不编号）**：逐集的 B0a 小说转剧本（write 剧本表）与 B0b 场景抽取/新角色（write 场景库/角色库/角色档案）。流程与对话确认模板一致——**写入前必须列清单并拿到用户明确确认**，授权铁律不放松。

## 四、对话确认模板（#1 #3）

```
--- 确认点 {N}: {标题} ---

{产出摘要：关键内容 + 数据量，如设定12项 / 30集 / 角色6个 / 本集12段}

本次如确认，将执行以下动作：
  1. [write] 表名 ×N 行（新增 X / 更新 Y）
  2. [generate] 对象清单（预估花费 ¥xx）
  3. [push] 同步到飞书
（只读预览动作可一并提示：可用 expand 查看提示词展开结果）

请回复：
  "确认" / "写入" / "执行" → 按清单执行
  "修改：<意见>"           → 只改草案，不写入，改完重新列清单
  "重做"                  → 重新生成草案，不写入
```

### 处理逻辑

- **"确认"类回复**：核对清单后逐条执行；执行完毕汇报结果（新增/更新/生成数量），回到沟通态。
- **"修改：XXX"**：把意见追加到 skill 输入重新产出草案；**不执行任何 write/generate/push**；产出新草案后重新发完整确认清单。
- **"重做"**：不带新约束重新生成草案，同样不写入。
- **讨论中出现的"可以/好/嗯"**：若上下文是在讨论方案而非面对写入清单，不视为授权，补问一句"是否按上面清单写入飞书？"
- **部分确认**：用户只确认其中一部分 → 只执行被确认的条目，其余保持草案。

## 五、飞书审核模板（#2 #4）

```
--- 确认点 {N}: {标题} ---

已生成 {数量} 个{资产类型}并推送到飞书。
请在飞书中查看并审核：
- 通过 → 保持"待审核"或改为"通过"
- 返工 → 将状态改为"返工"并填写审核备注

审核完成后回复"继续"。
```

### 处理逻辑

- **"继续"**：
  1. 执行 `python cli.py pull $WS` 拉取最新状态
  2. 检查是否有"返工"记录
  3. 有返工 → 读出审核备注，**列出返工重新生成清单（对象+预估花费），用户确认后**才重新生成
  4. 无返工 → 进入下一步
- 注意：generate/push 已在前一个对话确认中授权；"继续"本身不构成新的生成授权，返工重生成必须单独确认。

## 六、全自动模式（唯一例外）

用户在启动时说"全自动/不用确认/跳过确认"时：

1. 启动后先复述一次性总授权范围："将自动写入哪些表、自动生成哪些资产、预算上限"，用户无异议再开始
2. 跳过对话确认点（#1 #3）
3. **保留飞书审核点（#2 #4）**——图片/视频必须人眼检查
4. 用户在过程中随时说"停一下/手动"，立即恢复全部确认

## 七、反例（这些行为是错的）

- 用户说"主角设定改成 30 岁"→ 直接 `write 角色库`（❌ 应先改草案并重新列清单）
- 用户说"这个场景不太对"→ 直接 `generate` 重出图（❌ 应先改提示词草案，确认后再生成）
- 用户说"确认"后，顺手把用户没看过的下一集分镜也写了（❌ 一次授权只管一次清单）
- 同一份清单确认后，发现还要改两行，凭旧确认直接写（❌ 改动后重新确认）
