# 各 skill 数据交接格式与字段约定

harness 负责把上游 skill 的输出**在用户确认后**写入飞书、供下游 skill 读取。约定如下字段，保证衔接不丢信息。

## Automated Mode 输出规范

每个 skill 在 Automated Mode 下，除了产出人类可读 markdown，还必须额外输出一个 **结构化 JSON 代码块**（标记为 ` ```json:structured-output `）。harness 提取 JSON 后**只作为草案展示**，用户确认后才通过 `python cli.py write` 写入飞书。

## 0. 系统设置表（CLI 自动维护，技能不写）

「系统设置」表是项目级引导配置，由 `init` / `init-from-url` 自动写入，drama-initializer 等技能**不产出、不 write**：

| 配置项 | 配置值 | 说明 |
|---|---|---|
| `项目路径` | 本地 workspace 绝对路径，默认 `C:\Users\Heart\PycharmProjects\vomin_studio\workspace\{剧名}` | 凭飞书 URL 定位本地项目；迁移后用 `set-path` 更新 |
| `剧名` | 剧本名称 | 一个剧本一个 workspace 文件夹 |
| `创建时间` | 初始化时间 | — |

用户未指定路径时，workspace 一律默认落到 `项目根/workspace/{剧名}`；路径属于 init 写入清单，需在确认点 1 向用户列明。

## 1. 剧本初始化（drama-initializer → 剧本设定 / 资产库 / 角色档案）

drama-initializer 一次性产出**三段 JSON**（剧本表不在其内，由第 1b 节的 novel-to-drama 逐集产出）：

### 1a. 剧本设定（match key: `name`）

```json
[
  {"name": "剧名", "value": "重生打脸", "global_prompt": ""},
  {"name": "题材类型", "value": "都市·重生·逆袭", "global_prompt": ""},
  {"name": "画面风格", "value": "真人写实偏电影质感...", "global_prompt": "真人写实，电影色调，..."},
  {"name": "画幅", "value": "16:9 横版", "global_prompt": ""},
  {"name": "全集大纲", "value": "第1集：...；第2集：..."}
]
```

下游消费：drama-asset-generation（画风/画幅）、drama-asset-extraction、drama-segment-generation（世界观/节奏/看点）。

### 1b. 剧本表（novel-to-drama → 剧本表，match key: `episode`）

**Phase B · B0a** 逐集产出；**集与章不绑定**：一章可多集、多章可一集、章内可切分。不属于 drama-initializer。

> **字段以代码为准**：飞书表的字段唯一事实来源是 `vomin/feishu/bitable.py` 的 `TABLE_SCHEMA["剧本表"]`。本文件只描述 JSON 键与语义，不负责维护字段清单；要增删字段，先改 `TABLE_SCHEMA` 与 `pull_episodes` / `push_episodes`，再同步本文与各 skill 的产出说明。当前剧本表字段：`集号`、`集名`、`对应原小说章节`、`初版剧本`、`分镜设计稿`、`状态`。**原文不在本表**：小说章节逐字存在 `小说表`（`章节` / `标题` / `内容`）。

```json
[
  {
    "episode": "1",
    "title": "如果你不想要我，我可以走",
    "source_chapters": "1",
    "script": "转化后的初版剧本（经典剧本格式：场头/人物/△动作/台词/OS/字幕）",
    "status": "草稿"
  }
]
```

| JSON key | 飞书字段 | 说明 |
|---|---|---|
| `episode` | 集号（主键） | 集号；不必然等于章节序号 |
| `title` | 集名 | 4~14 字，勾人，不剧透结局 |
| `source_chapters` | 对应原小说章节 | 纯数字，逗号分隔升序：`1`、`1,2`；**由本集原文区间反推**，可跨多章，也可只取某章一部分；不要求从 1 开始或连续；**重做时重新反推，不继承旧值** |
| `script` | 初版剧本 | **转化后的剧本**，是资产提取与分镜的唯一剧本来源；抬头需含 `原文区间：第X章「起始句」→ 第Y章「结束句」` |
| `status` | 状态 | `草稿` → `已确认` → `已拆分镜` |

- 小说原文逐字进入 `小说表`，写入后不允许改写；`script` 是改编产物，可迭代修改。
- **先定原文区间，再填章号**：`source_chapters` 是结果，不是计划；区间不是阅读窗口，也不是整章范围。重做已有集时同样重新定区间，旧 `source_chapters` 只作参考。
- `status` 流转：`待转剧本`（存量行）→ `草稿` → `已确认` → `已拆分镜`。
- **读取口径**：`read --table 剧本表` 不含原文；需要原文时用 `read --table 小说表 --chapter <对应原小说章节>` 精确取，禁止通读全本。
- 用户上传的是**成品剧本**时：直接写 `script`，`source_chapters` 留空，不经 novel-to-drama。

### 1c. 资产库（唯一资产表，match key: `name`）

| JSON key | 飞书字段 | 说明 |
|---|---|---|
| `name` | 名称（主字段） | 资产名，锚点用它 |
| `kind` | 类型 | 角色 / 场景 / 道具 |
| `description` | 描述 | 一句可见描述（≤50 字） |
| `id` | ID | 数字，建表时分配 |
| `file_path` | 文件路径 | 出图后回填 |

```json
{"name": "陈诚", "kind": "角色", "description": "20岁男生，黑色微卷中长发，白T黑短裤，眉峰压低。"}
```

**锚点语法只有一种**：`{资产库：陈诚}`（角色/场景/道具共用，不再有 `{角色库：…}` 这类写法）。

下游按 `kind` 分流：分镜里角色走表演/可见性规则，场景走空间一致性，道具走外观一致性。

## 2. 资产出图（drama-asset-generation → 资产库）

`generate --target 资产库:名` 按 **类型** 自动选模板：

| 类型 | 模板 | 画面比例 |
|---|---|---|
| 角色 | 四视角设定图（近景正/侧 + 全身正/背） | 16:9 |
| 场景 | 场景资料图 | 22:9 |
| 道具 | 双视角图（正偏侧 + 正面） | 16:9 |

提示词由 `描述` + 模板自动拼，**不写进表**；出图后回填 `文件路径`。

## 3. 逐集资产提取 · 角色（drama-asset-extraction → 资产库）

**Phase B · B0b**：`drama-asset-extraction` 一次抽出本集的角色/场景/道具。本节是角色部分——读 `剧本表.script`，用 `对应原小说章节` 指向的 `小说表` 原文补长相（无对应章节只用剧本）。逐集增量，库里已有的同名角色复用。

只写资产库一行（描述），不写角色档案、不写音色、不写提示词。

| JSON key | 飞书字段 | 说明 |
|---|---|---|
| `name` | 角色ID / 角色名 | 与人名逐字一致 |
| `char_type` | 角色类型 | 核心 / 重要配角 / 配角 / 龙套 / 群像 |
| `appearance` | 外貌描述 | 一句，≤50 字，只写看得见的 |
| （不产） | 生成提示词 | 留空；出图时用 `appearance` + 全局画风自动拼 |

```json
{
  "characters": [
    {"name": "陈诚", "status": "新建", "char_type": "核心",
     "appearance": "18岁清瘦男生，黑色微卷中长发，白T黑短裤"}
  ],
  "reused": [{"type": "角色", "name": "沈幼怡", "reason": "资产库已有形象图"}]
}
```

规则：

- **只写描述（≤50 字）**，不写提示词、不写空间锚点、不写角色档案/音色；由 `check_assets.py` 卡死。
- **幂等**：每次先读资产库；同名（归一化后）标 `复用`，不写进 payload。写入按 `name` upsert，同名不会新增行。
- 同一人不同年龄/形态（`陈诚` / `陈诚 12岁`）拆成两个资产。
- 群像单列一行，`char_type=群像`，描述写人数、服色、队形。
- 配音如需固定音色，仍在 `角色档案` 里维护（初始化阶段已产出的不受影响）；本 skill 不再写档案。

## 4. 逐集资产提取 · 场景（drama-asset-extraction → 资产库）

**Phase B · B0b 的场景部分**：剧本定场景清单，当前集小说原文补空间细节（为空只用剧本）。

**match key**：`场景ID`（= 场景名），**一个场景一行一张图**。

### 资产库字段

| JSON key | 飞书字段 | 说明 |
|---|---|---|
| `name` | 场景ID（主键） | **场景名**；**不得含 `·`**；光影变体用全角括号，如 `出租屋（夜）` |
| `description` | 场景描述 | 一句，≤50 字：空间/材质/光线/无人 |
| （不产） | 生成提示词 | 留空；出图时用 `description` + 全局画风自动拼 |
| `ref_scenes` | 参考场景 | 生成该图时参考的其他场景名 |
| `relation_note` | 作用关联 | 作用 / 与其它场景共享哪些物件 |
| `related_episodes` | 关联集数 | 如 `1,3` |
| `gen_status` | 出图状态 | `待出图` / `生成中` / `已出图` / `需重抽` / `已通过` |
| `consistency` | 一致性检查 | `未检查` / `通过` / `不通过`；**不通过不得进入分镜生成** |
| `source` | 来源 | `AIGC生成` 等 |
| `ref_image` | 文件路径 | 出图后由 `generate` 回填 |

### 幂等

每次先读资产库；同名（归一化后：去空格、半角括号统一）标 `复用`，不写进 payload。写入按 `场景ID` upsert，同名不会新增行；`status=复用` 的行 CLI 会跳过。

### 场景引用语法

- `{资产库：出租屋（夜）}` → 直接命中该场景那一张图
- 不支持 `·母版` / `·主场景` / `·局部` 后缀
- 场景图与描述冲突时，以图为准

### 输出 JSON

```json
{
  "scenes": [
    {
      "name": "出租屋（夜）", "status": "新建",
      "description": "夜间出租屋，水泥墙浅灰木地板，南窗冷光，无人",
      "relation_note": "第1集场1、场3 挂参考",
      "related_episodes": "1,3"
    }
  ],
  "reused": [{"type": "场景", "name": "写字楼大堂", "reason": "已有场景图，复用"}]
}
```

### harness 动作（每步均需用户确认）

1. 写入资产库文字资产（不出图）：`write --table 资产库 --data '<资产库部分>'`
2. 出图（花预算，清单须列对象与预估花费）：`generate --target 资产库:出租屋（夜）`
3. **一致性检查**（出图后门禁）：入口/开门方向、地面材质与分界、功能区与门窗方位、光源方向、色调，逐图比对；任一不通过先修场景图，**不得进入视频生成**。详见 `drama-asset-extraction/references/scene-consistency.md`
4. 出图时机：懒加载——B1 产出 `dependencies` 后，只为本集用到的场景出图

## 4b. 逐集资产提取 · 道具（drama-asset-extraction → 资产库）

**用途**：存放反复出现、需要保持同一外观的道具（行李箱、蛋糕、粉色四件套、手机……）。不是每个道具都要入库——只收「跨镜头反复出现」或「需要单独出图」的。

**match key**：`name`（= `道具ID`，直接写道具名）

| 字段 | 说明 |
|---|---|
| 道具ID | 主键，= 道具名 |
| 道具名 | 与主键一致 |
| 道具类型 | 关键信物 / 手持道具 / 陈设道具 / 食物饮品 / 服装配饰 / 武器工具 / 电子设备 / 其他 |
| 道具描述 | 外形、材质、尺度、颜色、使用痕迹（只写看得见的） |
| 关联集数 | 如 `1,2` |
| 来源 | 原始采集 / AIGC生成 / 手动制作 |
| 生成提示词 | 出图用，可含 `{素材库：…}` 参考 |
| 负向提示词 | 可选 |
| 文件路径 | 出图后的相对路径（`ref/props/...`） |
| 生成模型 | 可选 |
| 出图状态 | 待出图 / 生成中 / 已出图 / 需重抽 / 已通过 |

```bash
# 写入（需确认；upsert，按道具名匹配）
python cli.py write $WS --table 资产库 --data '[{"name":"行李箱","prop_type":"手持道具","description":"24 寸硬壳，拉杆拉出三十厘米","related_episodes":"1","gen_prompt":"..."}]'

# 出图（花预算，需确认）
python cli.py generate --target 资产库:行李箱
```

提示词里引用：`道具：【P01｜行李箱：24 寸硬壳，{资产库：行李箱}】`；带图道具要写进 `【参考图映射】`。**空表也能跑**——没有行的道具只写文字、不挂锚点。

**幂等**：每次先读资产库，同名标 `复用`、不写进 payload；写入按 `道具ID` upsert，同名不会新增行。

## 5. 分段分镜与视频提示词（drama-segment-generation → 剧本分镜表）

**match key**: `shot_id`（= 段 ID，格式 `ep{两位集号}_p{两位段序}`，如 `ep10_p05`）

一段 = 一次生成任务 = 剧本分镜表一行；**段长按难度取 6~30 秒，30 秒是上限不是固定值**（单场景 1~2 人可吃满；换场景、≥4 人、群像、打斗、大特效拆短；参考图 >5 张必须拆段）。`drama-segment-generation`（剧本转提示词 4.2）一次产出分段提示词 + 依赖清单 + 资产绑定表：

```json
{
  "shots": [
    {
      "shot_id": "ep10_p05",
      "episode": 10,
      "timeline": "00:00-00:30",
      "prompt": "【第05段｜00:00-00:30｜隋朝皇宫大殿·质问】\n\n【本段资产锁定】\n【参考图映射】图1=S01隋朝皇宫大殿；图2=R01杨广；图3=R02姜颜\n场景：【S01｜隋朝皇宫大殿：{资产库：隋朝皇宫大殿}】\n角色：【R01｜杨广：{资产库：杨广 中年版}】【R02｜姜颜：{资产库：姜颜}】\n待补：【P03｜玉玺：待补，未读取】\n\n【本段整体基准】……\n【本段初始空间】……\n\n【镜头01｜00:00-00:02｜抬眼】\n近景固定机位，R01杨广位于画面中央……落幅停在他的眼睛。\n【对白 00:00.5-00:02】R01杨广（压着怒气、缓慢地说）：『人有南北，国有南北吗？』\n\n【本段终态】……",
      "status": "待生成"
    }
  ],
  "dependencies": {
    "scenes": [{"name": "隋朝皇宫大殿"}],
    "characters": ["杨广 中年版", "姜颜"],
    "props": ["行李箱"],
    "missing": [{"type": "道具", "name": "玉玺", "reason": "库里没有，标待补"}],
    "pending_images": [{"type": "场景", "name": "陈诚童年家厨房（日）"}],
    "new_scenes": [],
    "new_characters": [],
    "new_props": []
  },
  "asset_ids": [
    {"id": "S01", "name": "隋朝皇宫大殿"},
    {"id": "R01", "name": "杨广"}
  ]
}
```

`prompt` 字段是带换行的完整段文本，以段头 `【第NN段｜00:00-本段时长｜场景·事件】` 开头；`timeline` 写本段真实时长（6~30 秒）。多段即 `shots` 数组里多个对象。

### 段文本的固定骨架

```text
【第NN段｜00:00-00:30｜场景·事件】

【本段资产锁定】
【参考图映射】图1=S01场景名；图2=R01角色名；图3=R02角色名
场景：【S01｜场景名：{资产库：场景名}】
角色：【R01｜角色名：{资产库：角色名}】【R02｜角色名：{资产库：角色名}】
道具：【P01｜道具名：外形、尺度、数量，{资产库：道具名}】
待补：【P02｜库里没有的道具：待补，未读取】

【本段现场生成】没有独立图、本镜确需的可见内容（屏幕字、光斑、临时道具），写清取用层与重建层。

【本段整体基准】只写本段差异（时段/光比/天气/身份状态/尺度/声音），不重复全局画风词。
【本段初始空间】画面位置（画左/画右/中央/前中后景）、朝向、支撑、遮挡、开镜机位。

【镜头01｜00:00-00:02｜标题】
景别＋机位/运镜起笔，融合写：位置 → 动作 → 画面变化/物理反馈 → 停点。
00:00.5-00:02，R01角色名（情绪/语气地说）：『台词。』

【本段终态】位置/朝向/持握/道具/速度/伤势/特效，供下一段重建。
```

### 素材锚点语法

角色和场景条目里带锚点，CLI 展开时移除标记、收集素材，并把 `：】` 收干净：

| 写法 | 展开结果 | 收集的素材 |
|---|---|---|
| `【R01｜沈幼怡：{资产库：沈幼怡}】` | `【R01｜沈幼怡】` | 角色形象图 |
| `【S01｜陈诚公寓门口：{资产库：陈诚公寓门口}】` | `【S01｜陈诚公寓门口】` | 该场景那一张图 |
| `【P01｜行李箱：24 寸硬壳，{资产库：行李箱}】` | `【P01｜行李箱：24 寸硬壳】` | 道具参考图（资产库有该行且已出图） |
| `【P01｜行李箱：24 寸硬壳】` | 原样保留 | 无（道具没有参考图） |
| `{剧本分镜表：ep10_p04}` | 移除 | 该段已生成的图片/视频（动作衔接，能不用就不用） |
| `{素材库：素材ID}` / `{生图工作台：任务名}` | 移除 | 对应素材文件 |
| `音频参考：【R01沈幼怡：{音色库：音色名}】` | `音频参考：【R01沈幼怡】` | 音色库里的音频文件（`reference_audio`） |

规则：角色/场景**必须**带锚点且名称与库内逐字一致；道具**有图时**带 `{资产库：名}`，没图只写文字；锁定区有带图资产时**必须**写 `【参考图映射】`（图N 从 1 连续、顺序 = 锁定区出现顺序，带图道具也要列），否则模型无法对应参考图；补充内容写在锚点前（`24 寸硬壳，{资产库：行李箱}`），展开时 `：】`/`，】` 会自动收干净；正文一律写"编号+名称"（`R01沈幼怡`），不写裸名。

### 台词的机器格式

```text
00:01-00:02，R02陈诚（压着火、短促地说）：『你爸呢？』
00:09-00:10.5，R02陈诚画外音（画右门板后、压低地说）：『谁啊？』
00:18.5-00:20，R02陈诚（内心独白、嘴唇不动地说）：『沈幼怡。这三个字，』
```

- 行首 `起-止` 是时间窗，必须落在所在镜头内；不加 `【对白】` 前缀；
- 说话者 `编号+名称`，括号里必须有"说"；
- 画外音写 `…画外音（…地说）`，并在镜头段写明声音来自画左/画右/画上/画下；
- 内心独白写 `（内心独白、嘴唇不动地说）`；
- 本项目不做 TTS：对白由视频模型原生发声；需要固定音色时写 `音频参考：{音色库：音色名}`。

### 提示词里的其它约定

- `【本段整体基准】` 只写差异；全局画风由 `剧本设定` 在生成时追加，重复会稀释指令。
- 时长以 `时间线` 字段为准（`generate` 按真实秒数出片，上限 30 秒）。
- 分镜表不单独存台词字段；行首时间窗的台词行是唯一台词来源。
- `待补：` 行只用于库里没有的资产，**不写锚点、不占图号**；`preflight` 会把它们列为缺图。

harness 流程：
1. 读 `dependencies`，**差分比对资产库**：逐条检查 `scenes` / `new_scenes` 中每个场景名是否已存在、场景图素材是否已生成且一致性检查已通过
   - 缺失的场景 → 汇总待补清单，交 `drama-asset-extraction` 补出（一个场景一张图）
   - `new_characters` → 回 `drama-asset-extraction` 补描述，再用 `drama-asset-generation` 出四视角
   - `props` / `new_props` → 差分比对资产库；缺的列入**待补道具**（可手工补录或 `generate --target 资产库:名`），不阻塞分镜评审
2. 素材就绪后用 `python cli.py expand $WS --shot <id>` 预览锚点映射、确认 `【R01｜…】` 已收干净、素材齐全
3. 跑 `python skills/drama-segment-generation/scripts/check_segment_prompt.py <草稿>`，错误必须为 0（脚本按复杂度算段长上限；确需固定段长才加 `--target`）
4. 用户确认 → `write --table 剧本分镜表` → `generate` → `push`
5. 只有 `preflight` 全过、进入生产态，才在交付摘要里写 `12 项自检：PASS`

## 交接铁律

1. **原文不丢不改**：小说章节逐字进入 `小说表`（写入后不改）；剧本表用 `对应原小说章节` 记录本集用章；转化后的剧本进入 `初版剧本`，是下游唯一剧本来源；初始化（drama-initializer）只做提取不做改编
2. **全局资产只建一次**：设定卡、角色档案、核心场景不重复抽取，全流程引用复用
3. **画风全局继承**：角色/场景/道具资产图、视频提示词的画风一律取剧本设定 `画面风格`
4. **同景同名**：场景名称在 novel-to-drama 阶段归一化，场景清单、资产库、分镜环境锁定三处一致；场景名不含 `·`
5. **缺项不臆造**：任一 skill 缺关键字段，标注"未指定"并列入缺失清单，不替编剧脑补
6. **JSON 代码块标记**：Automated Mode 下必须用 ` ```json:structured-output ` 标记
7. **先确认后写入**：任何 `write/generate/push` 都以用户对写入清单的确认为前提
