# 格式与交付合同

这份文档只管“怎么写才能被下游稳定读取”，不管“戏好不好”。戏的判断在 `SKILL.md` 和 `references/method.md`。

## 两套格式，先分清

| 步骤 | 产物 | 格式 | 谁读 |
|---|---|---|---|
| Step A | 常规剧本（`drafts/epNN_script_plain.md`） | 本文第二节 | 人：读戏、对词、返工 |
| Step B | 切镜头版（`drafts/epNN_script.md`） | `cut-format.md` | 视频生成模型（下游 B1 直接拆段） |

**剧本表 `初版剧本` 字段写 Step B 的切镜头版。** Step A 只留在本地做对照。
切镜头版的台词、事件、场序必须与 Step A 逐字一致，只加镜头与描写。

## 一、剧本表字段

以 `vomin/feishu/bitable.py` 的 `TABLE_SCHEMA["剧本表"]` 为准：

| 飞书字段 | JSON key | 写什么 |
|---|---|---|
| `集号` | `episode` | 纯数字，如 `1` |
| `集名` | `title` | 4~14 字，勾人，不剧透结局 |
| `对应原小说章节` | `source_chapters` | 纯数字，逗号分隔升序：`1`、`1,2`、`2` |
| `初版剧本` | `script` | Step B 的切镜头版正文（见 `cut-format.md`） |
| `状态` | `status` | `草稿` |

**不写：**

- `小说内容`：原文在 `小说表`（字段 `章节` / `标题` / `内容`），不重复写到剧本表。
- `分镜设计稿`：**资产图就绪后**由分镜设计环节（`drama-director-design` / `drama-segment-generation`）生成并覆盖。重做剧本时保持原值——不清空、不写“作废”占位。
- `涉及资产`：资产提取环节维护。
- 任何提示词、资产锚点、镜头编号。

### 写入 JSON

```json
[
  {
    "episode": "1",
    "title": "如果你不想要我，我可以走",
    "source_chapters": "1",
    "script": "剧名：……\n第1集　……\n……",
    "status": "草稿"
  }
]
```

```bash
python cli.py write <WS> --table 剧本表 --data @ep01.json
```

写完必须 `read` 回读比对，不能只信本地 JSON。

## 二、Step A：常规剧本格式

> 这一节写的是“给人看的剧本”。切镜头版（Step B）在此基础上每镜加 `切镜头，` 与镜头描写，见 `cut-format.md`。
>
> 剧本按行解析。**在 Markdown 预览里连续行会被并成一段**：想看清排版就每行之间空一行（Step A 可选，不影响解析；切镜头版是必须）。

### 2.1 抬头

```text
剧名：养妹失策，社恐妹妹占有欲爆棚
第1集　如果你不想要我，我可以走
对应原小说章节：1
原文区间：第1章「门铃响，短促又怯生」→ 第1章「你哥哥会照顾好你的」
预估时长：约 88 秒｜4 场
```

- `第N集` 后用一个全角空格，再接集名。
- `对应原小说章节` 只写数字；一章用了一半也写该章。
- `原文区间` 写本集实际用到的起止句；**不是阅读窗口，也不是整章范围**。见下文「原文区间」。
- `预估时长` 写 60~120 秒之间的一个数；`｜N 场` 可省。
- 抬头之后空一行，进场次。

### 2.2 场头

```text
1．外景　陈诚公寓门口　日
```

四样东西，用全角空格分隔：

1. 场号 + `．`（全角句点）。
2. `内景` / `外景` / `内外景`。
3. 地点。
4. `日` / `夜` / `晨` / `黄昏` / `傍晚` / `清晨` / `白天` / `深夜`。

需要时在时间后加全角括号：

```text
3．内景　陈诚童年家厨房　日（闪回）
2A．外景　陈诚公寓门口　日（同时）
2B．内景　陈诚公寓玄关　日（同时）
```

- 一场 = 一个空间 + 一段连续时间。换空间另起一场。
- 交叉剪辑少用；用 `A/B` 标同时发生，不要滥用。
- 地点名与资产库一致，**不含 `·`**；同一地点的光影不同用 `（日）/（夜）` 区分。

### 2.3 人物行

```text
人物：沈幼怡、陈诚
```

- 只列本场出现或发声的人。
- 用顿号分隔。
- 没台词但在场、有反应的人也要列；不在场的人不要列。

### 2.4 备注行（可选）

```text
备注：八月末下午两点，地表四十度，热浪贴地
```

- 写时间、天气、光线、特殊状态（闪回/雨/断电/伤）。
- **不写机位、景别、运镜、情绪评价。**

### 2.5 本场预估（可选）

```text
本场预估：约 38 秒
```

- 给自己看，用来判断总时长；不写进正文。
- 全场相加与抬头差太多，说明节奏判断有问题。

### 2.5a 粗估时长（只用来判断，不用来凑）

- 一句台词：字数 ÷ 5~5.5 字/秒，再加约 0.3 秒呼吸。
- 一个动作/反应：1.5~3 秒。
- 一个 turn：5~15 秒，取决于台词和动作量。
- 60~120 秒通常 3~6 个 turn。先数 turn，再估秒；不要为了凑 90 秒加空镜、加水词、加重复反应。

### 2.6 动作行

每行以 `△` 开头，写**看得见、听得到**的事：

```text
△ 门开一条缝，陈诚堵在缝里，头发被汗黏在额角。
△ 门外，沈幼怡的手还悬在门铃上，没来得及收回。
△ 浅蓝碎花裙的后背湿了一片，行李箱立在右脚边，拉杆拉出三节。
△ 门要合上。沈幼怡伸手，把手机抵在门缝里。
```

规则：

- 现在时；一行一个动作或一个画面变化。
- 句子要短，能断就断；不用“于是”“接着”“过了一会儿”“与此同时”铺时间，直接切下一行。
- 写行为、物件、身体、空间；不写“她很紧张”“气氛凝固”“他心里一沉”。
- 每一行尽量回答：是谁、什么样、在哪、这一下之后画面停在哪。没看过小说的人只读这一行，能不能复述出发生了什么？
- **Step A 不写**景别、机位、焦段、运镜、切镜头（这些是 Step B 的事）。需要“信息切换”时才写 `△ 切到手机屏幕：……`，这是内容切换，不是镜头指令。
- 比喻、形容、作者评论一律不进动作行。
- 动作要能被演员做出来、被摄影机拍到。

**差 → 好：**

| 差 | 好 |
|---|---|
| △ 她心里很慌 | △ 她食指在裤缝上蹭了两下，指尖发凉 |
| △ 气氛凝固了 | △ 没人说话。陈诚手里的钥匙停在锁孔里，没拧 |
| △ 他愤怒地摔门 | △ 门板撞上门框，门上的旧漆落下一层细灰 |
| △ 她看起来很穷 | △ 行李箱的轮子缺了一个，用胶带缠着 |
| △ 一只手抓起白瓷碗 | △ 陈诚他爸的手抓起白瓷碗，指节粗，虎口一层薄茧 |

> **Step B 把这一节整体替换掉**：不再有 `△` 行，每个动作都写成一行 `切镜头，…`。写法见 `cut-format.md`。

### 2.7 台词

```text
陈诚（不耐烦）：「找错了吧？」
陈诚：「进不进？中暑了我可没钱送你去医院。」
```

- 格式：`角色（怎么说）：「台词」`；没有括号时 `角色：「台词」`。
- 冒号用全角 `：`；引号用 `「」`。
- 说话人写名字，不写“他”“她”。
- 括号里只写**怎么说**：情绪、语气、发声、气息。画外/电话可以写媒介或方位；不写动作、走位、原因、景别。
  - 情绪打底：不耐、克制、发沉、发苦、讥诮、局促……
  - 发声方式：压低、短促、慢半句、尾音落平、咬着字……
  - 气息/口型：喘息、咬牙、哭腔、气多声少……
  - 例：`陈诚（压到最低，慢半句，气多声少）：「你爸呢？」`、`陈母（电话里，声音低下来，少见地认真）：「诚诚。妈求你。」`
  - 情绪词要能指导表演；不写“复杂”“怅然”“状态不对”这类含糊词。
- 一句台词一行；不要把两句不同人的台词并到一行。
- 台词要能读出声；书面语、长从句、翻译腔要改。
- 改动只限虚词、语序、称呼，标【改】并记进交稿说明；不要借“顺口”改变人物的立场或信息。

### 2.8 OS

```text
陈诚（OS，压着火）：「沈幼怡。这三个字，是我亲手捂了六年的旧疤。」
```

- `OS` 写在括号最前面。
- 第一人称；短；口语。
- 写 OS 的那段，人物嘴是闭着的；不要一边说话一边 OS。
- 可以压缩、改人称、换语序；不得新增事实，不得替人物下结论。
- 不设每场配额；删掉后观众少了“决定/信息”才留，只少“情绪”就改动作。

### 2.9 画外音

```text
陈母（画外，电话里，声音低下来）：「诚诚。妈求你了。」
```

- 标明声源方位或媒介：画左/画右/门外/电话里/广播。
- 画外音也要有人在场或声源成立；不要用画外音把不在场的人硬塞进来。

### 2.10 字幕 / 屏幕字

```text
（字幕·手机）我是沈幼怡。
（字幕·微信，陈诚手机）幼怡九月份转去你们泰平一中……
```

- 写清是什么屏幕、谁的手机。
- 文字**逐字**写；不要概括成“一条消息”。
- 屏幕字算信息，不算台词；不要让字幕替人物说本该说出口的话（除非人物是哑巴/不能说话，这是人物设定）。
- 需要时写屏幕状态：字号、亮度、裂纹、膜有没有撕。

### 2.11 音效

```text
（音效）门轴响了一声。
（音效）手机在桌上连着震了三下。
```

- 只写有信息量的声音：门锁、脚步、手机震、玻璃碎、水开、电梯到。
- 不写“紧张的音乐”“悲伤的配乐”；配乐是后期的事。

### 2.12 结尾

```text
（本集完）
```

- 每集必须有。
- 后面不要加“下集预告”或作者旁白。

### 2.13 旧集兼容

已产出的旧集有两种老写法：`△` 动作行的纯剧本，或早期「切镜头，近景，门内，……」的分镜式写法。**不要为了统一格式重写用户已确认的集。**

- 新写的集一律走两步：Step A 用本文格式 → Step B 用 `cut-format.md`。
- 旧集重做时，按新两步法重出，不要在半旧稿上叠写。
- 用户要求统一旧集时，只重排表达（场头 / 人物 / △ 或切镜头 / 台词），不改事件、台词、顺序。
- 旧集的 `对应原小说章节` 可能是按“1 章 1 集”填的；重排时如果发现与剧本实际取材不符，先报告，不要顺手改字段。
- 不要在一集里混用两种格式。

## 三、命名与字段细节

### 集名

- 4~14 字。
- 可以是一句台词、一个动作、一个反常的画面。
- 不剧透结局；不用“第1集”“第一章”。
- 好例子：`如果你不想要我，我可以走`、`找错了吧`、`你爸呢`。
- 坏例子：`沈幼怡来到陈诚家`、`第一集`、`惊天反转`。

### 原文区间

```text
原文区间：第1章「门铃响，短促又怯生」→ 第1章「门被拉开」
原文区间：第2章「她把手缩回去」→ 第4章「门在他身后合上」
```

- **小说改编必写**；成品剧本（无对应章节）可省。
- 写本集**实际用到**的起止句，不是阅读窗口，也不是“从第X章开头到结尾”。
- 起止各取一句能定位的原文，**≤20 字**；太长就取开头几个字加 `……`。
- 跨章时写清起点章和终点章；中间章不用列，但 `对应原小说章节` 要补齐。
- 下一集从**结束句之后**开始；所以结束句要选“下一集能直接接”的位置。
- 区间是结果，不是计划：先定从哪句到哪句，再回填章号。
- **重做这一集时，重新定起止句**；不要拿旧 `对应原小说章节` 反推区间。

### 对应原小说章节

- 只写纯数字：`1`、`1,2`、`2`。
- 逗号用半角，升序，不重复。
- 不许出现“第1章”“1-2”“第2章后半”“1、2”。
- 一章只用了一部分，也写该章数字。
- 多章并一集，写实际用到的所有章。
- **不要求从第 1 章开始，也不要求连续**；本集用了哪几章就写哪几章。
- **字段是结果，不是计划**：先从原文区间反推章号，不要先定“第 N 集用第 N 章”再找内容。
- 原文区间的端点章号必须出现在这里；对不上，就是漏写或多写。
- **重做时重新回填**，不继承旧值；旧字段只作参考。

### 场景名

- 与资产库「名称」逐字一致。
- 不含 `·`。
- 同一空间的光影变体用全角括号：`出租屋（日）`、`出租屋（夜）`。
- 同一空间的不同区域，如果门/墙隔断，算两个场景：`陈诚公寓走廊`、`陈诚公寓玄关`。
- 不要写“主场景”“局部”“母版”这类后缀。

### 状态

- 新写的集一律 `草稿`。
- 用户确认后才改为 `已确认`；本 skill 不擅自改状态。

## 四、格式检查器

```bash
# Step A 常规剧本
python skills/novel-to-drama/scripts/check_script.py workspace/{剧名}/drafts/ep01_script_plain.md --mode plain

# Step B 切镜头版（同时对照 Step A，检查台词有没有被改动）
python skills/novel-to-drama/scripts/check_script.py workspace/{剧名}/drafts/ep01_script.md --mode cut --compare workspace/{剧名}/drafts/ep01_script_plain.md
```

不带 `--mode` 时自动判断：出现 `切镜头，` 行按切镜头版查，否则按常规剧本查。

它查**合同**：

- 抬头各行是否齐全（剧名 / 第N集 / 对应原小说章节 / 原文区间 / 预估时长）；
- `对应原小说章节` 是否纯数字；
- `原文区间` 是否写了起止句和 `→`，端点章号是否在 `对应原小说章节` 里；
- `预估时长` 是否在 60~120 秒；抬头 `｜N 场`、`｜N 镜` 与实际是否一致；
- 场头四要素是否成立；每场是否有 `人物：`；场景名是否含 `·`；
- 台词是否 `角色（…）：「…」` 格式；
- 是否有 `（本集完）`；
- **常规版**：动作行是否以 `△` 开头；是否混入景别/机位/运镜/`切镜头`（`切镜头` 出现在任何位置都算越界）；
- **切镜头版**：每镜是否**独立成行、顶格以 `切镜头，` 起头**、一行是否只有一个 `切镜头`、每行之间是否**空一行**（抬头也算）（不空行，Markdown 预览与飞书里会并段）、是否含景别、是否用代词指人、是否混入 `△`、时间码、段号、资产锚点、焦段；`强制一致：` 对象入镜时必写短语是否出现（缺了报错，标 `（不入屏）` 的降为警告）；镜头描写是否过薄；
- `--compare` 时逐句比对两份文件的台词与场头，台词被改会报错；
- 统计场数、镜数、动作/镜头行、台词、OS、字幕、字数。

它**不查**：

- 戏好不好、结构对不对、人物立不立得住；
- OS 该不该留、台词像不像人话；
- 钩子成不成立；
- 镜头选得美不美（那是 B1 `drama-segment-generation` 的事）。

格式过了，只说明下游能读；戏好不好，要靠 `SKILL.md` 的“六问”和读一遍。

常用参数：

```bash
# 把警告也当错误（交付前严格模式）
python skills/novel-to-drama/scripts/check_script.py <剧本.md> --strict

# 只看统计，不因警告失败
python skills/novel-to-drama/scripts/check_script.py <剧本.md> --stats

# 指定模式（拿不准时）
python skills/novel-to-drama/scripts/check_script.py <剧本.md> --mode cut
```

## 五、交付前清单

### Step A 常规剧本

- [ ] 抬头各行齐全；集名 4~14 字；对应章节是纯数字；原文区间写了起止句。
- [ ] 原文区间与对应原小说章节对得上；区间不是“整章范围”，也不是阅读窗口。
- [ ] 重做时，`原文区间` 和 `对应原小说章节` 一起更新；没有沿用旧值。
- [ ] 预估时长 60~120 秒；场数与 turn 数匹配。
- [ ] 每场都有 `人物：`；场头四要素成立；场景名与资产库一致、不含 `·`。
- [ ] 每场至少一次转移；没有“说明书场”。
- [ ] 开头三秒有变化/威胁；结尾钩子是本集后果。
- [ ] 台词/OS/字幕/音效格式正确；**没有镜头术语**（Step A 不写景别、机位、运镜）。
- [ ] `（本集完）` 在。
- [ ] `check_script.py --mode plain` 零错误。

### Step B 切镜头版

- [ ] 事件、台词、场序与 Step A 完全一致，台词一字未改。
- [ ] 每镜 `切镜头，` + 景别 + 名字 + 一个可见变化；没有 `△` 行。
