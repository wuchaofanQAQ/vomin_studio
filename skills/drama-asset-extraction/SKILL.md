# 剧本资产提取（角色 / 场景 / 道具）

## 定位

B0b 阶段的资产入口：先定"这一集要出哪些图"，再给每张图写**一句描述**。合并了旧的「剧本抽场景」与「小说抽角色」两套流程。

```text
剧本表·初版剧本（第 N 集：定有哪些角色/场景/道具）
  + 小说表·对应章节（第 N 集的 `对应原小说章节` 列出的章，若有：补长相、空间、道具细节）
  + 剧本设定（画风/画幅） + 资产库（判复用）
  → 资产清单：角色 / 场景 / 道具（+ 群像/生物/载具）
  → 每个资产：一句可见描述（≤50 字）
  → 确认后写库 → 按依赖懒加载出图 → 场景过一致性检查
```

**本 skill 只产描述**：不写出图提示词、不写空间锚点、不写人物小传与音色。出图时由生成环节用这句描述 + 全局画风自动拼。

## 六条铁律

1. **剧本定"有什么"，小说补"长什么样"**：场景清单、人物、道具、场次归属以剧本为准；小说只补布局、材质、外观、光线等被剧本压缩的细节。两边都没写 → 标"未指定"，不臆造。
2. **一个资产 = 一行 = 一张图**：场景按「空间 × 光影」拆，光影不同用全角括号后缀（`出租屋（日）` / `出租屋（夜）`）。
3. **只写一句描述（≤50 字）**：主体 + 关键外观 + 光线/视角，不写提示词、不写空间锚点、不写人物小传/音色，不写【】分节。
4. **复用优先、幂等写入**：库里同名且有图 → 直接复用，不改写描述、不重复插行；需求变了（光线/陈设/状态）→ 用新名新建，不覆盖旧资产。
5. **只抽要出图的**：台词只提一句的路人、纯背景人群、一次性陈设不进资产；反复出现、影响剧情、角色会拿起来/穿在身上、需要跨镜头保持一致的，才建。
7. **关联集数只填已有剧本的集**：只有「剧本表里已有剧本、且本资产真的用到」的集号才写；没用到、或剧本还没写的集，**留空**，不预填未来集数（如 `2,3`）。

6. **不改剧情**：不新增剧本没有的角色、场景、道具、事件；不替编剧补设定（缺的标"未指定"）。

## 资产判定

| 类型 | 什么时候要 | 命名 | 写入 |
|---|---|---|---|
| 角色 R | 有名字、有台词、有明确动作或被指认 | 与人名逐字一致；同名同人 | 资产库 |
| 群像 M | ≥3 个同类无台词个体（迎亲队、保镖、路人潮） | `群像名`，如 `迎亲队伍` | 资产库（char_type=群像） |
| 场景 S | 场头的地点 + 时间；一个空间一张图 | 地点，光影不同加 `（日）/（夜）`；**不含 `·`** | 资产库 |
| 道具 P | 反复出现 / 推动剧情 / 角色持有并使用 / 需要外观一致 | 道具名（不带尺寸） | 资产库 |
| 生物/灵兽 C | 有独立外观、会动、要跨镜头一致 | `名` | 资产库或资产库（按用途） |
| 载具 V | 有戏份的车辆/飞行器 | `名` | 资产库 |
| 特效 FX | 需要参考图的固定形态（法阵、光效、法相） | `名` | 不建行，写进描述与素材库 |

判定细节与合并/拆分规则见 `references/asset-rules.md`。

**不建资产的**：只被提到一次的地名/人名、纯背景虚化人群、路人、一次性桌面陈设、剧本没写的"应该有"的东西。

## 工作流

### Step 0 — 取料（只读，无需确认）

设当前集为 N：

```bash
python cli.py read $WS --table 剧本表 --episode N --context 1     # 拿到本集 script 与「对应原小说章节」，如 1,2
python cli.py read $WS --table 小说表 --chapter 1,2              # 只读这几章原文，不通读全本
python cli.py read $WS --table 剧本设定                            # 画风 / 画幅
python cli.py read $WS --table 资产库
python cli.py read $WS --table 资产库
python cli.py read $WS --table 资产库
```

- 小说原文只按 `对应原小说章节` 精确取（`--chapter 1,2`），**禁止通读小说表全本**；该字段为空（成品剧本）就只用剧本。
- N±1 集只用来判断跨集延续（上集结尾在走廊、本集开头接着拍），**不为它们建资产**。

### Step 1 — 逐场清点

扫 `初版剧本`（场头 `1．内景　地点　日` + `人物：` + `△` 动作行 + 台词 + 字幕）：

| 从哪读 | 得到 |
|---|---|
| 场头 | 场号、内/外景、地点、时间、备注（闪回/雨/强光） |
| `人物：` 行 | 本场出镜角色 |
| 台词行 | 说话角色（含画外/OS） |
| `△` 动作行 | 关键动作、道具、服装、身体特征、空间使用方式 |
| `（字幕…）` | 仅剧本阶段的记录；分镜里屏幕字要写进正文 |

### Step 2 — 归并与拆分

- **场景**：同一地点、同一时段、空间连通 → 一个场景；被墙/门隔断是两个空间；换光影拆名。
- **角色**：按姓名归并；别名（诚诚/哥哥）归到主名；同一人不同年龄段/形态算**不同资产**（`陈诚` / `陈诚 12岁`）。
- **道具**：同类只建一个（"手机"不按角色分），除非外观明确不同。

### Step 3 — 复用判定

逐个对库：

| 情况 | 处理 |
|---|---|
| 同名 + 已有图 | 复用，`status=复用`，不改写 |
| 同名 + 没图 | 补描述，`status=新建`（待出图） |
| 同名但本集光线/陈设/状态变了 | 新建 `（夜）` / `（雨）` / `（破损）` 等后缀的新资产 |
| 库里没有 | 新建 |
| 疑同一物但名字不同 | 先合并到已有名，在说明里写清；拿不准列"待确认" |

**幂等（多次调用）**：

- 每次都先读 `资产库` 再判新建，**不能凭剧本直接出新资产**；
- 名字归一后相同（去空格、半角括号统一成全角、英文小写）即视为**同一资产**，标 `复用`；
- **复用项不写进写入 payload**（只用于交付清单）；CLI 也会跳过 `status=复用` 的行，但不要依赖它兜底；
- 同一份输出里同名只能出现一次（校验器按归一化名字查重）；
- 同名但确实变了（夜间/破损/换装）→ 新建带后缀的名字，这是新资产，不是重复。

### Step 4 — 写描述

每个资产**一句**，≤50 字，只写看得见的信息：

- **角色**（写入 `appearance`）：年龄、体型、发型发色、服装、配饰、标志特征。
- **场景**（写入 `description`）：空间 + 材质 + 光线 + "无人"。
- **道具**（写入 `description`）：尺寸、材质、颜色、使用痕迹。

| 差 | 好 |
|---|---|
| 一个很帅的男生，气质忧郁，像从画里走出来 | `18岁清瘦男生，黑色微卷中长发，白T黑短裤` |
| 一间特别有氛围感的屋子 | `夜间出租屋，水泥墙浅灰木地板，南窗冷光，无人` |
| 【作用】本剧关键信物【材质】黑色硬壳 | `24寸黑色硬壳行李箱，拉杆拉出，箱角磨损` |

写法：

- 主体放最前，按"外观 → 服装/材质 → 光线/视角"排；
- 不写剧情、情绪、比喻、屏幕文字，不写空间锚点；
- 数一下（含标点、不含空格），**超 50 就删修饰**；
- 出图提示词不在这里写——生成时用这句描述 + 剧本设定的全局画风自动拼。

### Step 5 — 自检 + 机器校验

```bash
python skills/drama-asset-extraction/scripts/check_assets.py workspace/{剧名}/drafts/ep01_assets.json --library $WS
```

脚本校验：字段齐全、名字归一后唯一、场景名不含 `·`、描述 1~50 字且无【】分节、复用项有理由、待补项有说明；带 `--library` 时还会查幂等：**标新建但库里已有同名 → 报错**，标复用但库里没有 → 报错。**任一 ✗ 不许交付。**

### Step 6 — 交付与写入

对话里交付（缺一不可）：

1. **资产清单表**：类型 / 名称 / 新建或复用 / 一句描述（含字数）。
2. **待补/不确定**：剧本没写、需要用户拍板的项。
3. 结构化 JSON（写入用）：

```json
{
  "characters": [
    {"name": "陈诚", "status": "新建", "char_type": "核心",
     "appearance": "18岁清瘦男生，黑色微卷中长发，白T黑短裤"}
  ],
  "scenes": [
    {"name": "陈诚公寓门口", "status": "新建",
     "description": "老式公寓走廊，浅灰地砖，深灰防盗门，西端窗光，白天，无人",
     "relation_note": "第1集场1/4/5 挂参考", "related_episodes": "1"}
  ],
  "props": [
    {"name": "行李箱", "status": "新建", "prop_type": "手持道具",
     "description": "24寸黑色硬壳行李箱，拉杆拉出，箱角磨损", "related_episodes": "1"}
  ],
  "reused": [{"type": "场景", "name": "陈诚公寓玄关客厅（日）", "reason": "已有场景图，复用"}],
  "missing": [{"type": "场景", "name": "医院走廊", "reason": "剧本只提到一次，未建行"}]
}
```

### Step 7 — harness 写入与出图（需确认）

```bash
python cli.py write $WS --table 资产库 --data @characters.json
python cli.py write $WS --table 资产库 --data @scenes.json
python cli.py write $WS --table 资产库 --data @props.json
```

**只写新建项**：复用项不要出现在 data 里。写入按 `name` upsert，同名不会新增行；`status=复用` 的行 CLI 会直接跳过。

出图是 B1 之后的懒加载动作：只为本集 `dependencies` 用到的资产生成。**生成提示词字段留空**，CLI 用描述（+ 全局画风）出图；场景图出完必须过 `references/scene-consistency.md` 的一致性检查。

## 出图与一致性

- `gen_prompt` 留空即可，`generate` 会用 `appearance` / `description` 当提示词，并追加 `剧本设定` 的全局画风。
- 场景图出完后，按 `references/scene-consistency.md` 对照**场景描述**逐条比对；不过先修图，不得进入视频生成。

## Harness 接入

- harness 在 B0b 调用本 skill，拿到 JSON 后**先列写入清单**（角色/场景/道具各几行），确认后写三张资产表；
- B1 的分镜依赖 `dependencies`（scenes / characters / props），harness 差分后只为本集用到的资产出图；
- 已有资产复用，不重建；新资产缺图时列入"待补资产"。

## 不做的事

- 不写出图提示词、不写空间锚点、不写人物小传/音色。
- 不写分镜、不写视频提示词（那是 `drama-segment-generation` 的事）。
- 不抽不存在的资产；不把剧情、情绪、比喻写进描述。
- 不出图、不写飞书（确认后由 harness 执行）。
